## F08-S01: Song rhythm from ABC

## Notes

- **abcjs and later `Q:`** (probed on 6.7.2): `setUpAudio` has no tempo events but rescales the `start`/`duration` of every note after a mid-tune `Q:` (header line or inline). S01 removes `el_type: "tempo"` elements from the voices before `setUpAudio`; with them gone the durations are the written ones. `start` and `duration` are in whole notes. `tune.metaText.tempo` holds only the first `Q:`; `tune.getMeter()` the first `M:` (`common_time` for `C`, no `M:` and `M:none`; `cut_time` for `C|`).
- **Song shape:** a note carries `start` as well as `beats`, because slots run between starts (story Notes) and a rest leaves a gap between one note's end and the next start. `pitches` stays on `Song` so untimed code is unchanged.
- **Timed flow in its own file:** `src/app/timed-flow.ts` with `tests/app/timed-flow.test.ts`, rather than more branches in `card-flow.ts`. The design names `card-flow.ts`; the timed mode shares its types but none of its reveal, advance, tone or wait logic. The design's "card-flow tests" are these tests.
- **Clock:** the timed flow reads the audio context's `currentTime`, or `performance.now() / 1000` with no context (story Notes). Timers only wake the flow; boundaries are absolute times on that clock. `LEAD_SECONDS` (about 0.1 s) gives the context time to resume after the start tap before the first click.
- **Click sound:** a short noise burst from an audio buffer, not an oscillator, so it has no pitch the judge could settle on.
- **Summary staff:** the staff keeps the last note under "End of song" or the score; a tap shows the first note again for the count-in.
- **No-tempo note** shows in the Song section whenever the held song has no `Q:`, whether or not keep tempo is on; the example song has none, so it shows by default.
