## Sub-task 1: Settings core: types, validation and sharps snapping

Covers: S05-AC3, S05-AC4, S05-AC5, S05-AC6, S05-AC7, S05-AC8, S05-AC9, S05-AC10, S05-AC11, S05-AC12
- [x] Create `src/core/settings/index.ts`, importing only `../pitch` and `../instrument` (relative, no framework or browser API, no JSON import, no storage access: S05-AC11).
- [x] Types: `interface Settings { lowest: Pitch; highest: Pitch; includeSharps: boolean; delaySeconds: number }`; `class SettingsError extends Error`; constants `MIN_DELAY_SECONDS = 0.5`, `MAX_DELAY_SECONDS = 30`.
- [x] Serialized form (shared by the defaults file and storage): `interface SettingsJson { lowest: string; highest: string; includeSharps: boolean; delaySeconds: number }`, pitches as note names (`A3`, `C♯5`), like the instrument JSON. `toSettingsJson(settings): SettingsJson` writes names with `formatPitch`.
- [x] `snapToNaturals(lowest, highest): { lowest, highest } | null`: a sharp low bound moves up one semitone, a sharp high bound moves down one; returns null when the result has `lowest >= highest` (S05-AC7, S05-AC8).
- [x] `setIncludeSharps(settings, on): { ok: true; settings: Settings } | { ok: false; reason: string }`: on keeps the bounds (S05-AC9); off applies `snapToNaturals` and returns `ok: false` with a player-facing reason and no change when it is blocked (S05-AC8). Also `canTurnSharpsOff(settings): boolean` for the view.
- [x] `validateSettings(raw: unknown, instrument, defaults: Settings): Settings`, in this order:
  1. Each field separately: a non-object `raw`, a missing field, a wrong type, a pitch string `parsePitch` rejects, or a delay that is not finite in `[0.5, 30]` resets that field to its default (S05-AC6). `includeSharps` must be a boolean.
  2. Clamp each bound into the instrument's written range (S05-AC4).
  3. If `lowest >= highest`, reset both bounds to the defaults (S05-AC5).
  4. If `includeSharps` is false, snap the bounds; if blocked, reset `lowest`, `highest` and `includeSharps` to the defaults (S05-AC10).
  5. Valid input comes back equal to its parsed form (S05-AC3).
- [x] `parseDefaults(raw: unknown, instrument): Settings`: strict, throws `SettingsError` naming the field when anything is missing, wrong or would be changed by validation (the defaults file must be valid as written).
- [x] `tests/core/settings.test.ts`: one test per rule and edge case above, with the alto C instrument loaded from `data/instruments/ocarina-12-taiwanese.json`: unchanged valid input; clamp below A3 and above F5; low equal to and above high reset; delay 0.4, 0.5, 30, 30.5, `NaN`, `Infinity`, string, missing; non-object `raw`; bad pitch names; sharps-off snap of low, of high, of both; blocked snap (e.g. `C♯4`-`D♯4`) for the toggle and in validation; sharps back on keeps bounds; `parseDefaults` throws on each kind of bad input.
- [x] Extend the import assertion in `tests/core/core-imports.test.ts` only if needed; it already covers `src/core/**` for relative imports and browser globals (S05-AC11). Add a test in `settings.test.ts` that the module source contains no `.json` import.
- [x] Write `docs/architecture/modules/settings.md` (purpose, public interface, validation order, dependencies, tests) and add it to `docs/architecture/modules/README.md` (S05-AC12).
- [x] `make verify` passes.

## Notes

- Combining two stories in one progress file breaks the one-story-per-branch rule; the user chose it knowingly to go faster.
- S05-AC2 ("no settings button") is true after sub-task 2 and superseded by S06 in sub-task 4. It is verified at the sub-task 2 commit.
- Pitches are stored as note names, not MIDI numbers, matching the instrument JSON. The stored value and the defaults file share one shape.
- Delay is held in seconds (`delaySeconds`) and converted to ms only in the app. A stored delay off the 0.5 step (e.g. 1.3) is valid; the step applies only to the input.
- No DOM test library is in the toolchain, and adding one needs the user's agreement, so components are not unit tested. Picker and delay logic is pulled into `settings-form.ts` to be tested in plain Node.
- The view replaces the card while open rather than overlaying it, which makes "no longer driven" (S06-AC2) structural.
- If a stored setting is invalid, the corrected value is not written back until the player changes something.
