## F11-S02: Practice spots

Story: [`F11-S02-practice-spots`](../docs/features/11-score-analysis/stories/F11-S02-practice-spots.md)

Covers: AC1, AC2, AC3, AC4, AC5, AC6, AC7, AC8
- [x] Constants block in `src/core/analysis/index.ts`: `SPAN_BARS = 2`, `MAX_SPOTS = 2`, `SPOT_ALPHA = 0.05`, `MIN_BARS = 3`, `EXACT_BUDGET` (see next item; start at 2e6).
- [x] `mannWhitneyLower(span: number[], rest: number[]): number`, the one-sided p of the span being lower. Use mid-ranks over the pooled values. Work in doubled ranks so every rank is an integer, and compare values within 1e-9 as ties. The exact path is the conditional permutation distribution: a DP over the pooled doubled ranks counting the ways to choose `m` items with sum `s`, capped at the observed sum, as floats. P is the count at or below the observed sum over C(N, m). If the observed sum is at least the null mean, return the normal value instead, since it cannot be significant. When `N * m * cap > EXACT_BUDGET`, use the normal approximation with the tie-corrected variance and a 0.5 continuity correction (AC2, AC7). Record both paths and the budget in the module doc.
- [x] `practiceSpots(input)`: bars from `songBars(input.song)`, each bar's start in ms `bar.start * 60000 / tempo`. Every graded `result.items` entry (note or rest) belongs to the last bar whose start is at or before its `startMs` (1e-6 ms slack). With fewer than `MIN_BARS` bars, return `{ tested: false, spots: [] }`. Candidates are bars `i, i+1` for each `i` from 1 to the bar count minus 1. Skip a candidate with no graded item, or with none outside it. K is the number tested. A spot needs `p < SPOT_ALPHA / K` (Bonferroni, chosen over Holm for simplicity; with at most two spots the difference is small). Sort by p, then lower mean coverage, then earlier bar, and pick greedily without sharing a bar, up to `MAX_SPOTS`. Each `Spot { firstBar, lastBar, startBeat, endBeat, coverage, elsewhere, p }`: bars counted from 1 over `songBars`, `startBeat` the first bar's start, `endBeat` the next bar's start or the song's end (for S04's shading), and `coverage` and `elsewhere` the mean coverage in and outside the span (AC1, AC3, AC4, AC5). `analyse` gains `practice: { tested, spots }`.
- [x] Tests in `tests/core/analysis.test.ts`, from item coverages placed in bars (a small helper builds a `CoverageResult`-shaped `items` list and a song with N bars): one clearly bad span found; the same with noise; one bad item alone not found; uniformly low and uniformly high, none (AC6); two bad spans far apart, both, lowest p first; two overlapping, one; a two-bar song `tested: false`; ties at 0 and 1; a pickup bar counted as bar 1; ordering ties broken by mean then bar. P-values (AC7): exact against a brute-force enumeration of every subset, in the test, for small samples with and without ties (1e-12); against published table values with no ties (m = 3, n = 4: P(U ≤ 0) = 1/35, P(U ≤ 1) = 2/35); the normal path against a value worked by hand from the tie-corrected formula and written in the test (1e-6), and within 0.01 of the exact path at m = 8, n = 40.
- [x] Update `docs/architecture/modules/analysis.md`: the rule, the bar membership, the correction choice, both p-value paths with their precision (AC3, AC8).
- [x] `make verify` passes (AC8).

## Notes

- **AC4 amended at breakdown (2026-11-23, by the user, on this branch):** the start offset is the start of the unbroken run of the right pitch into the first right reading, so early starts and rushing show. The design's Start habit and Modules touched were updated to match. Coverage gains `ItemScore.soundStartMs`.
- **Rest sound needs coverage too:** segments mark pending readings as `silent`, so S01 AC3 (wrong or pending) cannot come from segments; coverage gains `ItemScore.soundedMs`, additive like `soundStartMs`.
- **Slurred graces:** inside a slurred join's grace, coverage counts the neighbour's pitch as covered; the breakdown counts that time by its segment kind (silent or wrong). Breakdown shares are time-weighted and coverage is a per-item mean, so they were never going to match.
- **Gap habit** keeps AC6's wording (next note's first right reading). When the next note starts early, the time its pitch sounds before the join is counted as gap, so a player who rushes into notes shows a longer gap than they left.
- **Choices left to the breakdown by the design:** Bonferroni correction; exact conditional p-values with a normal fallback above a size budget; shading in the overlay with `multiply` blending.
