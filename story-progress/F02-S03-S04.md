## Sub-task 3: Service worker, registration and update behavior

Covers: S04-AC1, S04-AC2, S04-AC5, S04-AC6, S04-AC7, S04-AC8
- [ ] `vite.config.ts`: set `VitePWA` `workbox` options: `globPatterns: ["**/*.{js,css,html,ttf,txt,png,svg,webmanifest}"]` so the font, its license text, icons and manifest are precached; `cleanupOutdatedCaches: true`; `skipWaiting: false` and `clientsClaim: false` so a new worker waits and takes over on a later launch with no reload and no prompt (ADR 0004); `navigateFallback` to the base `index.html`. Keep `devOptions.enabled` false so `make dev` has no worker.
- [ ] Create `src/app/register-sw.ts` (plain TypeScript, no framework): `registerServiceWorker(env)` where `env` is `{ navigator, isProd, baseUrl }` injected like `loadFont`. It does nothing when not production or when `serviceWorker` is absent, otherwise calls `register(`${baseUrl}sw.js`, { scope: baseUrl })` and swallows rejection and a throwing call, so the app still runs (S04-AC7). It never calls `skipWaiting`, shows UI or reloads.
- [ ] `src/app/main.tsx`: after `render`, call `registerServiceWorker({ navigator, isProd: import.meta.env.PROD, baseUrl: import.meta.env.BASE_URL })`. Keep `main.tsx` free of other logic.
- [ ] `tests/app/register-sw.test.ts`: a fake `navigator` records `register` calls. Cases: not production, no `serviceWorker`, normal registration (URL and scope `/fingerwise/`), rejecting `register`, throwing `register` (never throws out).
- [ ] `tests/pwa/precache.test.ts`: build with the Vite `build` API into a temp `outDir` (not `dist/`), read the generated `sw.js`, and check its precache list names the `.ttf`, the `OFL-*.txt`, the three icons and `manifest.webmanifest`. Give it a generous timeout. Extend `tests/node-modules.d.ts` for the extra `node:fs` and `node:os` functions it uses.
- [ ] `make build` and `make preview`; with `curl -s localhost:4173/fingerwise/sw.js | head` confirm the worker is served from the base.
- [ ] Extend `docs/architecture/deployment.md`: the service worker, what is precached, the registration scope, the silent-update rule (waits, takes over on a later launch, old caches cleaned), registration only in production, and how to test update behavior locally (the S04 note).
- [ ] Update `docs/architecture/modules/app.md`: `registerServiceWorker` in Public interface, its tests, and the by-hand checks. Leave the vision's feature 2 line as a pointer to the design and deployment doc (it already is; confirm and trim any remaining detail).
- [ ] `make verify` passes.

## Notes

- Combined on `story/F02-S02-phone-tablet-layout` at the user's request, bending the one-story-per-branch rule. S02's own checklist still has unticked items (its hand checks); S02 acceptance is separate.
- Icon tool: system ImageMagick through `make icons` (user's choice). The PNGs are committed, so CI and `make build` never need it. No new project dependency beyond `vite-plugin-pwa`.
- Manifest colors `#2b2b2b` and `#f2e8d5` are taken from the existing `public/favicon.svg`; adjust if `app.css` uses other colors.
- Sub-task 2's build already emits a service worker that nothing registers; this is harmless and is wired in sub-task 3.
- `skipWaiting: false` is my reading of "takes over on a later launch" in ADR 0004. S04-AC5 says "by the second launch", which matches a waiting worker that activates once the old copy's windows close. Hand-test it; if installed copies take too long to update, raise it rather than changing the criteria.
- `tests/pwa/precache.test.ts` runs a real build, so `make test` gets slower by several seconds. If that is unacceptable, replace it with a config-only check.
