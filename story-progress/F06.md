## F06-S01: Need scores and weighted draw

Story: [`F06-S01-need-scores-and-weighted-draw`](../docs/features/06-smart-sampling/stories/F06-S01-need-scores-and-weighted-draw.md)

Covers: AC1, AC2, AC3, AC4, AC5, AC6, AC7, AC8, AC9, AC10
- [x] Create `src/core/progress/index.ts`, importing only `type Pitch` from `../pitch`:
  - `export const ALPHA = 0.3` and `export const FLOOR = 0.05` (names as in ADR 0007), defined once (AC3).
  - `export type ProgressGrade = "correct" | "miss"` (not the judge's `Grade`; AC9).
  - `export type Scores = ReadonlyMap<Pitch, number>` and `emptyScores(): Scores`.
  - `needOf(scores, pitch): number`: the stored need, or 1 when absent (AC1).
  - `applyGrade(scores, pitch, grade): Scores`: copies the map, sets `n + ALPHA * (target - n)` with target 0 for `correct`, 1 for `miss` (AC2, AC5).
  - `resetScores(): Scores`: returns `emptyScores()` (AC4, AC5).
  - `drawWeight(scores, pitch): number`: `Math.max(needOf(scores, pitch), FLOOR)` (AC3).
- [x] In `src/core/drill/index.ts` add `drawWeighted(pool, previous, weight: (p: Pitch) => number, random): Pitch` beside `drawPitch`, no import of `progress`:
  - Empty pool throws `DrillError`; a one-pitch pool returns it (AC7).
  - Candidates are the pool minus `previous`; any candidate weight that is not finite and `> 0` throws `DrillError` (AC7).
  - If every candidate weight is equal, return `drawPitch(pool, previous, random)` so the index is exactly `Math.floor(random() * n)` (AC8; avoids float drift in a cumulative sum).
  - Otherwise `target = random() * total`, walk the candidates subtracting weights, return the first where the running sum exceeds `target`; fall back to the last candidate for float rounding (AC6).
- [x] `tests/core/progress.test.ts`: absent pitch is 1; the AC2 sequences (0.7, 0.49, 0.343, 0.2401; 0.08 → 0.356 with `toBeCloseTo`); boundaries (correct at 0 stays 0, miss at 1 stays 1); `drawWeight` floor at 0.01 and passthrough above; reset reads 1 for any pitch; input map unchanged after `applyGrade` and `resetScores` (AC5); source imports only `../pitch`, never mentions `judge`, `Math.random`, `Date` or `performance` (AC9).
- [x] Extend `tests/core/drill.test.ts`: weighted draw proportions under a stepping random (e.g. weights 1, 3 over 4000 steps give ~1:3), every candidate reachable, previous never drawn, one-pitch pool returns previous, empty pool and `0`, negative, `NaN`, `Infinity` weights throw (AC6, AC7); equal weights match `drawPitch` for a sweep of random values including 0 and just below 1 (AC8); the existing "never calls Math.random" and import checks still pass, plus drill source does not contain `../progress` (AC9).
- [x] Check `tests/core/core-imports.test.ts` and `tests/extensibility/drill-layers.test.ts` pick up the new folder with no change (glob over `src/core/**`) (AC9).
- [x] Write `docs/architecture/modules/progress.md` (purpose, interface, dependencies `../pitch` only, tests; storage shape to follow in S03); add it to the list in `docs/architecture/modules/README.md`; describe `drawWeighted` in `drill.md` interface and tests (AC10).
- [x] `make verify` passes (AC10).

## Notes

- Storage: key `fingerwise.progress`, shape `{ "<instrument name>": { "<written pitch>": need } }`. The instrument's `name` ("12-hole alto C ocarina") is the key, so renaming an instrument in its JSON orphans its scores. No version field, matching `fingerwise.settings`.
- Other instruments' stored entries are copied through unvalidated on save, since only the current instrument's definition is loaded.
- The reset confirmation is the native `window.confirm` (the story leaves this choice to the breakdown): accessible, no new UI state, works in an installed PWA.
- The existing song-in-use line in Cards is reworded to name smart sampling too, so one line covers all three disabled controls (S02 AC5).
- Scores live in a ref in `App`, not state: a grade must not re-run the flow effect, which would deal a new card.
- The equal-weights path in `drawWeighted` delegates to `drawPitch` so AC8 holds exactly, not just within float error.
- F07 "waiting" (S04 AC5) is not built yet; song cards just keep their current tune order and get no `onGraded`. Agreed with the user: AC5 is checked on that basis, and F07's waiting must not grade when it is built.
