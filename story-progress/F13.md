## F13-S01: The playback schedule

Story: [`F13-S01-playback-schedule`](../docs/features/13-play-the-song/stories/F13-S01-playback-schedule.md)

Covers: AC1, AC2, AC3, AC4, AC5, AC6, AC7, AC8, AC9, AC10, AC11

- [x] `src/core/song/index.ts`: `export const JOIN_GAP_MS = 50` and `interface PlaybackTone { pitch; startMs; lengthMs; endMs }`, where `endMs` is the note's written end (start plus written length), for the flow's end and sounding note. `playbackSchedule(song, fallbackTempo): PlaybackTone[]`: tempo `song.tempo ?? fallbackTempo` (AC6). One tone per note, in order, with the written pitch (AC1). `startMs = note.start * 60000 / tempo` and `writtenMs = note.beats * 60000 / tempo`. The note is *joined* only when it is `slurred`, is not the last, and the next note starts at its written end, within `BEAT_EPSILON`. A joined note's `lengthMs` is `writtenMs` (AC3). Every other note's `lengthMs` is `writtenMs - min(JOIN_GAP_MS, writtenMs / 4)`: a plain join (AC2), the last note (AC4), or a note before a rest, even when slurred (AC5). Not rounded. The source still imports only `../pitch` and `../instrument` (AC7).
- [x] `tests/core/song.test.ts`, `describe("playbackSchedule (F13-S01)")`: equal quarters at 120 (starts 0/500/1000, lengths 450, last 450), mixed lengths, a slur (full length) and the plain note after it, a rest after a slurred note (gap kept), the last note slurred by flag (gap kept), a sixteenth at ♩ = 160 (93.75 ms written, gap 23.4375), no `Q:` with fallback 90 (AC1 to AC6). The existing import test covers AC7.
- [x] `src/audio/tone.ts`: move `play`'s node and envelope code into a private `startTone(ctx, pitch, t0, seconds): Tone`, and `stop`'s fade into a private `fadeOut(ctx, tone)`. `createTonePlayer` uses both and behaves exactly as now (its tests stay unchanged).
- [x] `src/audio/tone.ts`: `createToneScheduler(audio): ToneScheduler` with `schedule(pitch, atSeconds, seconds)` and `stop()`. `schedule` follows the lock rule as `play` does (AC10) and calls `startTone(ctx, pitch, atSeconds, seconds)`, keeping no "current" tone, so tones may overlap (AC8). Each tone goes into a `pending` set and leaves it in `onended`. `stop()` empties the set (AC9). A tone whose start is after `ctx.currentTime` is stopped with `osc.stop(now)`, so it never sounds. A sounding tone gets `fadeOut`, the same `FADE_SECONDS` fade as `TonePlayer.stop`. Every Web Audio call is in a `try/catch` (AC10). The scheduler shares the one context but not the player's state: `play`/`stop` and `schedule`/`stop` never touch each other's tones.
- [x] `tests/audio/tone.test.ts`, `describe("createToneScheduler (F13-S01)")` on the fake context. Three tones: frequency, `"sine"`, start and stop times, and each envelope's ramp times (AC8). Two tones that touch at a slur, both still scheduled, with neither stopped by the other (AC8). Then `stop()`: a sounding tone fades and stops at `now + FADE_SECONDS`, a pending one stops at `now`, a second `stop()` does nothing (AC9). The lock rule: locked and never unlocked gives no nodes, while unlock requested on a suspended context does schedule (AC10). `createOscillator` throwing, and a throwing `stop`, never escape (AC10). A player tone survives a scheduler `stop()`, and the reverse.
- [x] Docs (AC11): `docs/architecture/modules/song.md`: `JOIN_GAP_MS`, `PlaybackTone`, `playbackSchedule`, the tests; `SongNote.slurred` is now read here, so drop "Nothing reads it yet". `docs/architecture/modules/audio.md`: `createToneScheduler` under `tone.ts`, scheduled tones in the lock rule, the tests.
- [x] `make verify` passes (AC11).

## F13-S02: The Play song button

Story: [`F13-S02-play-song-button`](../docs/features/13-play-the-song/stories/F13-S02-play-song-button.md)

It holds one timer slot, and `at` cancels any pending one first. When it fires before the clock reaches `time`, it re-arms. `timed-flow.ts` uses it, replacing its `timer`, `at` and `cancel` (keeping its `stopped` checks), and imports `CLOCK_EPSILON` from it. The `timed-flow.test.ts` tests pass unchanged. Add `tests/app/clock-timer.test.ts`: it fires at the time, re-arms on a lagging clock, a second `at` replaces the first, and `cancel` works.
- [x] New `src/app/playback-flow.ts` (plain TypeScript): `createPlaybackFlow({ song, clock, clicker, tones, sounding, metronome, onChange, onEnd }): { start(), stop() }`. `tones` is `{ schedule(pitch, atSeconds, seconds); stop() } | null` and `sounding` is `(written) => Pitch`. `PlaybackState { phase: "count-in" | "playing"; origin }`.
  - `start()`: `tempo = song.tempo ?? DEFAULT_TEMPO`, `bar = countIn(song.meter, tempo)`, `t0 = clock.now() + LEAD_SECONDS` (both from `timed-flow.ts`). One click per count-in beat from `t0`, then `firstSlot = t0 + bar.beats * bar.beatMs / 1000` (a pickup still gets the full bar). It emits `count-in` with `origin = firstSlot` (AC2).

  - With `metronome`, a click at `firstSlot + k * beatMs` for every beat strictly before the last note's written end; without it, none after the count-in (AC3).
  - Tones and beats are scheduled in batches, up to a time plus `METRONOME_LOOKAHEAD_SECONDS`: at `start()` for the first note, then at each note's start through the clock timer. The first note's start emits `playing`.
  - At `firstSlot + last endMs / 1000`, `onEnd()` is called once.
  - `stop()`: cancels the timer, calls `clicker.stop()` and `tones.stop()` and sets `stopped`. Nothing more is emitted, scheduled or ended, and a second `stop()` is harmless (AC4).

## Notes

Assumptions (defaults, no ADR needed):

- **Interim screen (S02).** While the song plays in S02, the card area is empty: header, button and footer only. S03 fills it, as S02's notes say.
- **Sounding note.** A note is black from its start to the next note's start. It is not greyed in the 50 ms join gap, which would flicker on repeated notes. It is greyed only during a written rest. The count-in shows the first note black, not the count-in rests.
- **End.** Playback ends at the last note's written end, not its tone's end, which is shorter by the gap.
- **Stop.** "At once" is a 20 ms fade (`FADE_SECONDS`) for a sounding tone, so it does not click. A tone not yet started is stopped outright.
- **Slurs.** A slurred tone lasts exactly its written length, and the next tone starts as it ends; the two fades meet. If that dips audibly, the hand check says so. An overlap beyond the written length would change the schedule's criteria, so it is not done here.
- **Own clicker.** Playback has its own clicker, so the drill flow's cleanup (`clicker.stop()`) cannot cut the count-in, whatever order the effects run in.
- **Web Audio.** "Without Web Audio" means `browserAudioFactory()` is null. A context that fails later plays silently on the page clock, and the visual still runs.
- **The button while Settings is open.** It is hidden, like the Settings button itself.
- **Narrow header.** Below 480 px the button is its icon only, with an `aria-label`.
- **Shared timer.** The re-arming clock timer moves to `clock-timer.ts`, so both flows share it rather than copy it.
