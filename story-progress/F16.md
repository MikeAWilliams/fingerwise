## F16-S03: Single note with the microphone on

Story: [`F16-S03-single-note-listening`](../docs/features/16-setting-clarification/stories/F16-S03-single-note-listening.md)

- [ ] `src/core/judge/index.ts` holds the tone rule (AC13). Add `TONE_END_SILENCE_MS` (start at 150, a live-check value) and `SINGLE_NOTE_PASS_SHARE = 0.75`. Add `type ToneOutcome = "passed" | "too-short" | "wrong"` and `gradeTone(readings, { expected, toleranceCents, lengthMs, checks })`. `expected` is the sounding pitch. Each reading lasts until the next one's time. Sounding time is readings passing `passesChecks`; time within tolerance is those `judge` grades correct. The result is `passed` when time within ≥ share × `lengthMs`, `too-short` when time within is more than half the sounding time, and `wrong` otherwise (AC4, AC5, AC6, AC10). It imports nothing outside `../pitch` and `../instrument`.
- [ ] Same module: `createToneWatch(options: StabilityOptions, endSilenceMs = TONE_END_SILENCE_MS)` with `reset(startMs)` (the hold-off applies), `push(reading)` returning `{ kind: "start"; startMs }`, `{ kind: "end"; readings }` or null, and `tone()` returning `{ startMs; readings } | null` for the live trace. A tone starts once sounding readings have lasted `settleMs`; `startMs` is the first of them. It ends only after `endSilenceMs` of non-sounding readings, never on a change of pitch. A shorter sound is dropped and reports nothing (AC3).

## Notes

- **Field names:** `mode` (`"flashcards" | "song"`), `practice` (`"single" | "tempo"`), `fingeringDelaySeconds`, `singleAdvanceDelaySeconds`. `keepTempoApplies` is renamed `tempoApplies`.
- **Old data:** `keepTempo` sets the practice whenever it is a boolean, even with use song off, so a hidden keep tempo carries over as a hidden Tempo practice (the same idea as AC7).
- **The tone rule lives in `src/core/judge`** (the design left it to the breakdown). It uses the judge's tolerance, `passesChecks`, the settle time and the hold-off, so no new module or import rule is needed.
- **Segment width (decided by the user 2026-11-25):** Single note uses Tempo's lane segments, which end where the release starts. The trace's full width is the written length (S03 AC2) and the 75% is of the written length, so a long tone's trace can run past the grey segment into the release gap.
- **A song that fails at load:** this happens only if the ABC rules change after a save. Song mode then has no song and shows no drill, as it does while parsing, and Settings shows the problems.
- **End of song:** no note is black and no head shows until a tap restarts.
- **No component test environment** (no DOM in Vitest): the "view tests" are tests of the pure helpers (`settingsSections`, `practiceControls`, `singleNoteView`, `headPlace`, `toneSegment`, the strip geometry). The rendering is checked by hand.
- **Hand checks:** written once at Closing as `story-progress/F16-checks.md`, with no stops between stories.
- **Live-check constants:** `STRIP_HEIGHT`, `TONE_END_SILENCE_MS`, `SINGLE_NOTE_PASS_SHARE`.
