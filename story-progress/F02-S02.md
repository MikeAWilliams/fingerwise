## Sub-task 2: Card and staff sizing

Covers: AC1, AC3, AC4, AC8
- [ ] `src/render/staff/index.ts`: after `renderer.resize(WIDTH, HEIGHT)` call `renderer.getContext().setViewBox(0, 0, WIDTH, HEIGHT)` so the SVG scales with CSS. Drawing coordinates are unchanged. `make verify` and a look at the staff in `make dev` show it still draws the same at the default size.
- [ ] `src/app/app.css`: `.card` is centered with `max-width` (about 28rem) and `margin: 0 auto`. `.card-staff svg { width: 100%; max-width: 440px; height: auto; }` so it is 220 px wide at its natural size up to 360 px screens, and larger on tablets but capped (not stretched). Pick the `.card-staff` height to match the scaled staff using one rule keyed on width (for example `aspect-ratio: 220 / 150` on `.card-staff` with the same max-width), not JS. Staff box size depends only on viewport width, never on `revealed`.
- [ ] `.card-reveal` keeps a fixed height per breakpoint (rem units), the glyph and name sizes grow a step in a `@media (min-width: 600px)` block. The reveal area never changes height between hidden and revealed.
- [ ] Phone landscape (about 640x360): content is taller than the screen, so allow the page to scroll vertically with nothing cut off (no `overflow: hidden`, no `100vh` heights). If the staff and reveal fit with a `@media (max-height: 480px)` tweak (smaller reveal height and glyph), add it; otherwise vertical scroll is accepted by AC4.
- [ ] Footer wraps and stays inside the page width.
- [ ] `make verify` passes.
- [ ] Hand check in responsive mode at 360x640, 640x360, 768x1024, 1024x768: whole staff visible, no sideways scroll, card centered, staff larger on tablet but bounded, reveal does not move the staff (toggle by clicking).
