## F05-S02: ABC to song

Story: [`F05-S02-abc-to-song`](../docs/features/05-songs/stories/F05-S02-abc-to-song.md)

Covers: AC1, AC2, AC3, AC4, AC5, AC6, AC7, AC8, AC9, AC10, AC11
- [x] `bun add --exact abcjs` (the one new dependency, agreed in ADR 0006); confirm `package.json` holds an exact version and `bun.lock` changed only for abcjs (AC1).
- [x] Create `src/abc/index.ts` (outside `src/core`; it may import `../core/song`, `../core/pitch`, `../core/instrument`). Types: `interface AbcProblem { message: string; line: number; note?: number; column?: number }` and `type AbcResult = { ok: true; song: Song; notes: number; converted: number } | { ok: false; problems: AbcProblem[] }`. `parseAbc(text: string, instrument: Instrument): Promise<AbcResult>`, async because of the dynamic import (AC1, AC10).
- [x] Load abcjs only with `await import("abcjs/src/api/abc_tunebook.js")`, cached in a module variable. The file is CommonJS: take the API as `mod.default ?? mod` so it works both under Vitest and in the Vite build (check both, not just the tests). Add a `src/abc/abcjs.d.ts` (`declare module "abcjs/src/api/abc_tunebook.js"`) declaring only the fields read (`parseOnly`, the tune's `setUpAudio`, `warnings`, `lines`, and the events' `pitch` and `startChar`); check the real field names against `node_modules/abcjs` and the [spike](../docs/research/abcjs-parsing-spike.md) before typing them, and log a real parse once while writing the code rather than guessing the tree shape (AC10).
- [x] Pitches: `parseOnly(text)`, then `tune.setUpAudio({})`; take the MIDI numbers of the single track's note events in order. MIDI number is the app's `Pitch` directly (sharp spelling), so no accidental or repeat code is written (AC2, AC3, AC5, AC6). Verify against the spike table; no transposition (ADR 0003).
- [x] Positions: map each event's `startChar` to a 1-based line, and a note number counting written notes in text order (the number the player sees in the editor), through a helper `locate(text, startChar)`. Note numbers come from the parse tree: every note element (a chord counts as one, rests and grace notes do not count), sorted by `startChar`, numbered from 1. Every `AbcProblem` carries the position the story names (AC7, AC8, AC9).
- [x] Rejections from the parse tree, each a problem with its position and a plain message: more than one tune, more than one voice or staff or track, a note element with more than one pitch (chord), a note with `gracenotes`, a decoration of D.C., D.S., fine, coda or segno, and no note events (AC7). The warning text of abcjs is stripped of markup and reported with its line and column; anything abcjs warns about is rejected, and a throw from abcjs becomes one problem, never an exception (AC9).
- [x] Limits: over 10,000 characters is rejected before parsing; over 500 notes (song length, after repeats) is rejected after. Export `MAX_ABC_CHARS = 10000` and `MAX_ABC_NOTES = 500` from `src/abc/index.ts`; S03 replaces `MAX_ABC_CHARS` with an import of the settings constant (AC7).
- [x] Range: `songOutOfRange(song, instrument)` from S01, one problem per offender naming the pitch with `formatPitch`, its position and "below" or "above" the written range (AC8).
- [x] Converted count: for each event, find its written note in the tree by `startChar`; count it when the letter of the sharp spelling of the MIDI number differs from the written letter (B♭ to A♯, E♯ to F, double sharps and flats). Counting is per event, so a converted note inside a repeat counts each time it is played, matching `notes`, which is the song length (AC4).
- [x] `tests/abc/abc.test.ts` (Node, no DOM, so no environment override): octaves `C`, `c`, `C,`; at least three hand-written tunes for key signatures, bar-carried accidentals, naturals and a mode (`K:Ddor`) with the pitch lists written out by hand; flats in key and marked, E♯ and B♯, double accidentals, and the converted counts; repeats with first and second endings; rests, slurs, decorations, chord symbols, lyrics, dynamics and triplets unchanged; a tie within a bar and across a bar line; CRLF, tabs and trailing blank lines accepted; every rejection of AC7 with its position; out-of-range offenders listed with side; plain prose and malformed text give a warning problem and never throw; the two limits (AC2 to AC9).
- [x] Import check for AC10: `tests/abc/abc-imports.test.ts`, scanning `src/**/*.{ts,tsx}` as raw text (as `tests/core/core-imports.test.ts` does), asserts that `abcjs` appears in exactly one import, `import("abcjs/src/api/abc_tunebook.js")` in `src/abc/index.ts`, and in no static `from "abcjs…"` import. No build is run in this story's tests; the chunk and precache checks come from the measurement below and S03's precache test.

## Notes

- **Adapter location (design leaves it to the breakdown):** `src/abc/index.ts` with a module doc `abc.md`, a sibling of `src/audio` and `src/render`, importing only `src/core`. It is outside `src/core`, so it may import abcjs; `src/core` never imports it.
- **`nextInOrder` shape (S01 AC3 says "returns the pitch"):** it returns `{ index, pitch }` so the caller can keep the index the story's notes ask for. A test for each AC checks both.
- **Note number:** counts written notes in text order, not played notes after repeats, so it matches the editor's view of the tune. The line is 1-based.
- **Measuring in S02 (AC10, AC11):** nothing in the app references the adapter until S03, so the real app build only contains the abcjs chunk after S03. S02 measures with a temporary import that is removed, and S03 adds the permanent precache test. The numbers reported to the user come from S02.
- **When abcjs loads:** on first need, which is a saved song at page load or the first edit of the text box. The design says "when the Song section opens"; the section's open state is internal to `Section`, so loading on the first edit is the nearest cheap equivalent. The summary shows "off" or "on" for a closed section, so no parse is needed to render it.
- **Settings file shape:** `useSong` and `songAbc` are plain fields in `Settings` and `SettingsJson`, like the others. The parsed `Song` is app state, not a setting.
- **Dependency:** abcjs only, exact version, no other tool or package.
- **Song validity lives in app state, not settings:** a non-empty `songAbc` does not mean a valid song (S03 AC4 keeps a failing stored text). App's `song: Song | null` is what decides whether the toggle is enabled (S03) and which source the card flow uses (S04).
- **S04 by-hand checks not done:** the by-hand item (paste a tune with flats, an out-of-range tune, watch the loop, change the song, turn use song off) was not run; left for acceptance together with S03's.
- **S03 by-hand checks not done:** fw-execute is hands-off and has no browser here. Left for acceptance: text box, link opening in a new tab, disabled states, screen-reader text, closing and reopening with a failing text (S03 AC5 to AC10). The state logic is covered by `tests/app/song-form.test.ts`; the app wiring is not covered by component tests.
- **S03 state shape:** `App` holds one `SongState { song, summary, problems }` instead of separate `song` and `songProblems`, so the Song section can show the saved song's summary (with its flat count) when reopened. `onSong` receives the whole state. `applySongText` takes `result: AbcResult | null` (null for an empty box) and returns `{ settings, state, problems }`.
- **Measured sizes (S02):** abcjs chunk `abc_tunebook-<hash>.js` 211.04 kB minified, 60.74 kB gzip (spike: about 211 kB and 61 kB), plus the adapter's own chunk 4.83 kB, 2.14 kB gzip. Precache 18 entries (839.07 KiB) to 20 entries (1051.45 KiB), +212.38 KiB. No `modulepreload` in `dist/index.html`; `dist/sw.js` lists the chunk. For S03's precache test, match `/assets\/abc_tunebook-[^"']*\.js/`.
- **S02 choices:** `setUpAudio({ chordsOff: true })`, since a chord symbol such as `"Am"` otherwise adds a second track. Lists of more than 10 problems are cut to 10 plus an "and N more problems" line, since prose gives one warning per character. The text is normalised to `\n` line endings before parsing so abcjs offsets match the lines reported.
