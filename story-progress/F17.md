## F17-S02: Load a song file

Story: [`F17-S02-load-a-song-file`](../docs/features/17-load-abc-song-file/stories/F17-S02-load-a-song-file.md)

Covers: AC1, AC2, AC3, AC4, AC5, AC6, AC7, AC8, AC9, AC10, AC11, AC12, AC13

- [ ] `src/abc/index.ts`: add `type ProblemKind` and `PROBLEM_KINDS`, the ordered labels of AC4 (chords, grace notes, second voice, unmatched slur, D.C. or D.S., ABC errors, no notes, too many notes, out of range, unreadable). Give `AbcProblem` an optional `kind`, set where each problem is made: warnings → ABC errors; chord, grace note, second voice (both places), slur, forbidden decoration in `structuralProblems`; no notes, too many notes, out of range and `thrownProblem` → unreadable. The character-limit problem and the "and N more" line have none. Typed-text results are otherwise unchanged.
- [ ] Same file: give `readTune` an option `collectAll`. With it, problems from warnings and structure do not end the reading: it still sets up the audio (a throw then adds "unreadable" only when nothing else was found) and checks the note count and the range on the events' pitches against the instrument directly, without `createSong`, so a tune with chords and a note out of range names both (AC4 example). Without the option, behaviour is as today.
- [ ] Same file: `loadAbcFile(rawText, instrument): Promise<FileLoad>` with `FileLoad = { ok: true; text; loaded: number; total: number; cut: boolean } | { ok: false; reason: "no-tune" | "first-too-long" }`. Normalise CRLF to LF. Split as abcjs does, on `\nX:`: the header (text before the first `X:`, which may be empty) and one chunk per tune, each running to just before the next `\nX:`, so prose between tunes stays with the tune before it (AC7). Read the chunks one at a time, in order: a chunk already in the dropped shape (`droppedTitle`) is kept; otherwise parse `header + chunk` alone with `parseOnly` and `readTune(…, collectAll)`, using the uncut problem list so kinds beyond the first 10 count (AC5). A passing chunk is kept as written (AC2). A failing one has its tune part (up to its first blank line) replaced by its own `X:` line and `T:<title> (not loaded: <kinds>)`, the title being the first `T:` line's text or "Tune N", the kinds each once in `PROBLEM_KINDS` order, comma-separated (AC3, AC4); the rest of the chunk is kept. Append each resulting chunk while the text stays within `MAX_ABC_CHARS`; at the first that does not fit, stop reading (AC6). `loaded` is the chunks kept, `total` the chunks in the file, `cut` whether any were left off. Fail `first-too-long` when the header plus the first chunk does not fit, and `no-tune` when no kept chunk passes (AC8).

## Notes

- **Result shape:** a dropped tune is `{ dropped: true; title }` in the ok result's `tunes` and in `SongState.tunes`, told apart with `isDroppedTune`. The song core is unchanged.
- **Dropped shape and prose:** the dropped test looks at the tune's text up to its first blank line, where abcjs ends a tune. Prose after a blank line does not stop a tune being dropped, and the loader keeps it.
- **All tunes dropped** fails with one "No notes found" problem on line 1 with no tune number, as an empty text does.
- **Kinds of a failing tune:** today a tune with a warning or a structural problem stops there, so its range is never checked. AC4's example ("chords, out of range") needs both, so the loader reads with `collectAll`. Typed text keeps today's problem lists.
- **Cutting:** the unit is a tune with the text after it up to the next `X:`. If the passing tunes all lie after the cut, nothing passes, and the load fails with "No tune in the file could be loaded."
- **Line endings:** the loaded text has LF line endings; a `textarea` reports LF anyway, so a CRLF file is "unchanged" as AC2 means it.
- **Large files:** the loader stops reading at the first tune that does not fit; it does not yield to the page between tunes.
- **No component test environment:** the button, the pickers in a real browser and the messages on screen are hand checks.
- **Platforms:** hand checks use Firefox and Chrome on Linux desktop; phones are not checked (AC12's phone case is covered by the fallback path's tests).
