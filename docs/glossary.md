# Glossary

Terms used across the docs. Add to this as the domain firms up.

| Term                           | Meaning                                                                                          |
| ------------------------------ | ------------------------------------------------------------------------------------------------ |
| **Pitch**                      | The internal note representation every layer converts to and from.                               |
| **Sounding pitch**             | The pitch that actually comes out of the instrument.                                             |
| **Written pitch**              | The pitch shown on the staff. The fingering table is keyed by it. Sounding pitch = written + transposition ([ADR 0003](architecture/decisions/0003-written-pitch-and-transposition.md)). |
| **Transposition**              | The semitone offset from written to sounding pitch. Required in every instrument definition; a future ocarina-key setting (C/F/G) would select it. |
| **Glyph**                      | The character in the tablature font that draws one fingering ([ADR 0002](architecture/decisions/0002-tablature-from-panzi-font.md)). |
| **Note range**                 | The lowest and highest written pitch the player has chosen to drill, with sharps included or excluded. |
| **Fingering**                  | The hole pattern (open/covered) that produces a pitch on an instrument.                          |
| **Tablature (tab)**            | A drawn diagram of a fingering.                                                                  |
| **Japanese / Taiwanese style** | The two common fingering systems for 12-hole ocarinas.                                           |
| **Instrument definition**      | A JSON data file describing an instrument (range, fingering table, transposition, default clef). |
| **Card**                       | One drill item: a pitch to be fingered.                                                          |
| **Reveal**                     | The step after the delay where the note letter and tablature are shown.                          |
| **Reveal delay**                  | Seconds between a card appearing and its automatic reveal. Set in settings, 0.5 to 30, default 3. Called "delay" in older docs. |
| **Auto-advance**               | Showing the next card on its own after the advance delay, with no click or key press. A setting, default on. Off with the microphone running gives a **retry** ([F18](features/18-retry-and-tempo/design.md)). |
| **Advance delay**              | Seconds between a reveal and the automatic next card when auto-advance is on. 0.5 to 30, default 3. |
| **Sound delay**                | Seconds from the reveal to the start of the tone. 0 to 30, default 0.5. |
| **Sound duration**             | Seconds the tone plays. 0.5 to 30, default 1.5. While play note and auto-advance are both on, sound delay + sound duration must be at most the advance delay. |
| **Judge**                      | Listening to the microphone before the reveal, deciding what pitch was played and grading the card ([F04](features/04-record-and-judge/design.md)). |
| **Listening window**           | The part of a card's life when the judge uses microphone readings: from the card's appearance until its reveal. The microphone stream itself stays open across cards while drilling. |
| **Verdict**                    | The judge's result for a card: correct, incorrect, or none (nothing heard).                      |
| **Tolerance**                  | How many cents from the expected pitch a played tone may be and still be correct. A setting.     |
| **Settle time**                | How long a detected pitch must stay clear, loud enough and steady before it counts as a played tone. 200 ms, from the [F04 spike](research/pitch-detection-spike.md). |
| **Hold-off**                   | A short time at the start of each listening window when readings are ignored, so the room tail of the previous tone is not judged. 500 ms from the card's appearance. Single note uses none, since it plays no tone. |
| **Cents**                      | A hundredth of a semitone, the unit for how far a tone is from a note.                           |
| **Song**                       | One tune, an ordered list of notes (written pitch, start and length in quarter-note beats) with its tempo and meter, read from the player's ABC text ([F05](features/05-songs/design.md), [ADR 0008](architecture/decisions/0008-songs-keep-rhythm.md)). When the text holds several tunes, the song is the chosen tune ([ADR 0010](architecture/decisions/0010-several-tunes-in-one-text.md)). |
| **Chosen tune**                | Of a song text with several tunes, the one in use as the song. Picked from a list in the pinned header, saved by its position in the text; a tune without a `T:` is listed as "Tune N" by position. Planned in [F14](features/14-tune-choice/design.md). |
| **Dropped tune**               | A tune in the song text that is just an `X:` line and a `T:` line, written by the file loader in place of a tune that failed; its title names the kinds of problem. Listed in the header's tune list but cannot be chosen ([ADR 0013](architecture/decisions/0013-dropped-tunes-from-a-file.md)). Built in [F17-S01](features/17-load-abc-song-file/stories/F17-S01-dropped-tunes.md). |
| **Mode**                       | The first choice in Settings: **Flashcards** or **Song**, and **Tuner** from [ADR 0014](architecture/decisions/0014-tuner-mode.md). Each setting belongs to the mode it affects, and only the chosen mode's settings are shown; microphone settings apply to both ([ADR 0012](architecture/decisions/0012-two-practice-modes.md)). Built in [F16-S01](features/16-setting-clarification/stories/F16-S01-mode-first.md). |
| **Tuner (mode)**               | The third mode ([ADR 0014](architecture/decisions/0014-tuner-mode.md)): no target and no score. It shows the nearest note to whatever is played, on the staff with its tablature, and its offset in cents, following the tone live and holding the result when it stops. Planned in [F19](features/19-tuner-mode/design.md). |
| **Flashcards (mode)**          | Random cards from the note range, uniformly or by smart sampling, with the reveal, play note, delays and progress. A song never sets their order. Built in [F16-S01](features/16-setting-clarification/stories/F16-S01-mode-first.md). |
| **Song (mode)**                | Practising the chosen tune, always shown whole as a scrolling song, in **Tempo** or **Single note** practice. It never plays a note except through Play song. Built in [F16-S01](features/16-setting-clarification/stories/F16-S01-mode-first.md). |
| **Practice**                   | The song mode choice between **Tempo** and **Single note**, replacing the keep tempo checkbox. Built in [F16-S01](features/16-setting-clarification/stories/F16-S01-mode-first.md). |
| **Tempo (practice)**           | Song practice in time, as keep tempo works today: count-in, moving playhead, metronome and scoring. Built in [F16-S01](features/16-setting-clarification/stories/F16-S01-mode-first.md). |
| **Single note (practice)**     | Song practice with no clock: the play head stays on one note until it is played right. With the microphone on, a tone within tolerance for at least 75% of the note's segment (its written length less the release) moves it on; a right tone that is too short asks the player to play the note's whole value, and a wrong one shows the fingering. With it off, the fingering shows after the fingering delay and the head moves on after the advance delay. Built in [F16-S02](features/16-setting-clarification/stories/F16-S02-single-note-view.md) (microphone off) and [F16-S03](features/16-setting-clarification/stories/F16-S03-single-note-listening.md) (microphone on). |
| **Tone end**                  | In Single note, a tone ends after a short silence (a code constant, tuned live), never on a change of pitch; a sound shorter than the settle time is not a tone. Built in [F16-S03](features/16-setting-clarification/stories/F16-S03-single-note-listening.md). |
| **Pass (Single note)**        | A finished tone passes when its time within the tolerance is at least 75% of the note's segment, its written length at the tempo less the release (a code constant, tuned live); a tone held longer still passes. Right but shorter asks for the whole value; mostly wrong shows the fingering. Built in [F16-S03](features/16-setting-clarification/stories/F16-S03-single-note-listening.md). |
| **Fingering delay**            | In Single note practice, seconds from a note becoming current until its fingering shows, unless it was passed first. Its own setting, apart from the flashcard reveal delay. Built in [F16-S01](features/16-setting-clarification/stories/F16-S01-mode-first.md). |
| **Fingering strip**            | In Single note practice, the space under every line's score lane where the current note's letter and tablature are drawn, kept whether or not a fingering shows. Built in [F16-S02](features/16-setting-clarification/stories/F16-S02-single-note-view.md). |
| **Use song**                   | A setting: cards follow the saved song in order instead of the random pool. Default off; disabled with no valid song. Replaced by the **Mode** (Song) in [F16-S01](features/16-setting-clarification/stories/F16-S01-mode-first.md); old stored data is read once to map it. |
| **Example song**               | "Mary Had a Little Lamb", the song text in the defaults, so use song works without pasting a tune. An empty stored song text loads as it ([F07](features/07-song-practice/design.md)). |
| **Waiting**                    | A song card's state, with use song and judging on, until the correct note is played or the player skips. A wrong note does not end it ([F07](features/07-song-practice/design.md)). Replaced by **Single note** practice in [F16-S02](features/16-setting-clarification/stories/F16-S02-single-note-view.md); the song card is gone. |
| **Hint**                       | The note letter and tablature shown on a waiting card after the reveal delay or a tap, while it keeps listening. Unlike the reveal, no tone plays and nothing advances. Replaced by the fingering shown in Single note practice ([F16-S02](features/16-setting-clarification/stories/F16-S02-single-note-view.md)); the song card is gone. |
| **Skip**                       | A tap on a card showing the hint: the next song note is dealt at once, with no tone. Replaced in [F16-S02](features/16-setting-clarification/stories/F16-S02-single-note-view.md) by a tap in Single note practice, which shows the fingering and then moves on. |
| **Keep tempo**                 | A setting: with use song on, each song card lasts its note's length at the tune's tempo and the song moves on regardless; graded within the slot when judging is on ([F08](features/08-timed-play-along/design.md)). Default off. Replaced by the **Tempo** practice in [F16-S01](features/16-setting-clarification/stories/F16-S01-mode-first.md); old stored data is read once to map it. |
| **Tempo**                      | How fast a song is played, from its ABC `Q:` line; ♩ = 90 when it has none ([ADR 0008](architecture/decisions/0008-songs-keep-rhythm.md)). A **chosen tempo** may replace it. |
| **Chosen tempo**               | The tempo picked from the header's Tempo list in Song mode, in place of the tune's own: steps of 5 from half to 1.5× the tune's tempo, capped where the shortest note would be too short to grade, with the tune's own marked "(tune)". Saved; reset by another tune or an edit of the song text. Planned in [F18](features/18-retry-and-tempo/design.md). |
| **Retry**                      | In Flashcards with auto-advance off and the microphone running, a missed card stays after the reveal and keeps listening until the right note is played (or a tap). It still counts as a miss. Planned in [F18](features/18-retry-and-tempo/design.md). |
| **Slot**                       | With keep tempo, the time a song note's card is shown and listened to: from its start to the next note's start, so a rest's time goes to the note before it. |
| **Coverage**                   | In a timed song, the share of a note's written length filled with the right note (nearest the expected pitch, in tune or not), or of a rest filled with silence, edges aside. Tuning is reported apart, as the in-tune share of the right-note time. The song's coverage is the mean over graded notes and rests ([ADR 0009](architecture/decisions/0009-timed-songs-scored-by-coverage.md)). |
| **Scoring lag**                | A fixed allowance for audio latency: each reading is placed on the song's timeline this long before it arrived ([F09](features/09-timed-scoring/design.md)). |
| **Edge grace**                 | A short time (40 ms) at each edge of a note or rest not counted in its coverage, for release tails and the previous pitch blurring through the analyser. At a note's end that is not slurred, the **release allowance** takes its place. |
| **Release allowance (release)** | The end of a note not slurred into the next, where the player may stop to tongue or breathe: 25% of its written length, at most half a quarter note at the tempo, at least the edge grace. Silence there is forgiven, sound there still counts, "ended early" is measured from its start, the lane's segment ends there and playback stops there ([ADR 0011](architecture/decisions/0011-release-allowance.md)). Planned in [F15](features/15-release-allowance/design.md). |
| **Join**                       | Where one song note meets the next: **plain** (a silence is required, even at the same pitch) or **slurred** (no break, the pitch changes). A tie makes one note, so it has no join. |
| **Separation**                 | A detected gap, silent readings or a dip in level, at a plain join. |
| **Timing fault**               | A note that started late, started early, ended early or ended late, beyond a tolerance after the scoring lag. |
| **Playhead**                   | The vertical line moving through a timed song's staff at the time the player hears. |
| **Score lane**                 | The strip under each staff line where each note's and rest's segment fills as it is played. On a note the fill is a pitch trace: its height follows the cents offset over about ±150 cents, green in tune, amber out of tune but the right note, red beyond ±50 cents, and pinned to an edge when further off. |
| **Pinned header**              | The app header, pinned to the top of the screen: the name, the Settings button, the tune's title (with use song on and a `T:` line; with several tunes, the list of tunes instead, see **Chosen tune**) and, while keep tempo applies, the tempo. Planned in [F10](features/10-scrolling-song-view/design.md). |
| **Pinned bar**                 | The bar pinned to the bottom of the screen during a timed song: the start prompt, the live readout, the summary and tuning list, and the legend. Planned in [F10](features/10-scrolling-song-view/design.md). |
| **Score analysis**             | The section under the music at the end of a timed song that explains the score: where the note time went, playing habits and practice spots. Planned in [F11](features/11-score-analysis/design.md). |
| **Practice spot**              | Two bars in a row whose coverage is significantly lower than the rest of the song (a one-sided rank test), named in the score analysis and shaded on the staff. Planned in [F11](features/11-score-analysis/design.md). |
| **Tempo drift**                | The trend of note start offsets over a timed song: getting later is slowing down, earlier is rushing. Planned in [F11](features/11-score-analysis/design.md). |
| **Scoring**                    | A setting for timed songs with judging on: **Live feedback** (the lanes fill as you play) or **After the song** (music only while playing, everything judged at the end). Default Live feedback. Planned in [F12](features/12-score-after-the-song/design.md). |
| **Overrun**                    | With scoring after the song, playing that carries on past the song's last beat. Listening continues until 1 s of silence (10 s at most), and the overrun is shown in its own lane but not scored. Planned in [F12](features/12-score-after-the-song/design.md). |
| **Playback**                   | With use song on, the app playing the tune itself after the **Play song** button is pressed: a count-in, then each note as a sine tone at the tune's tempo, tongued at plain joins, while the music follows. Nothing is listened to or scored. Planned in [F13](features/13-play-the-song/design.md). |
| **Count-in**                   | One bar of clicks in the tune's meter before the first note of a timed song. |
| **Metronome**                  | A setting under keep tempo: a click on every beat while the song plays, not just the count-in. Default off. Under **Tempo** practice from [F16](features/16-setting-clarification/design.md). |
| **ABC notation**               | A plain-text format for tunes, used by tune books and online editors. Only its pitches are used. |
| **Pool**                       | The set of pitches a card can be drawn from: the naturals between the low and high bounds, plus the sharps between them if sharps are included. |
| **Smart sampling**             | A setting: with judging on, random cards are drawn weighted by need instead of uniformly ([F06](features/06-smart-sampling/design.md)). Default off. |
| **Need**                       | A pitch's score from 0 to 1 for how much work it needs; 1 when never graded. Moved towards 1 by a miss and towards 0 by a correct answer ([ADR 0007](architecture/decisions/0007-smart-sampling-by-need.md)). |
| **Drill engine**               | The code that builds the pool and draws the next pitch. Knows only pitch and instrument definitions, never clef, staff, audio or UI. |
| **PWA**                        | Progressive Web App: a website that can be installed to the home screen and run offline ([ADR 0004](architecture/decisions/0004-pwa-with-vite-plugin-pwa.md)). |
| **Service worker**             | A script the browser keeps that serves cached files when there is no network. Exists only in the production build. |
| **Precache**                   | Storing every built file in the service worker's cache on first load so the app runs offline.   |
| **Story**                      | A small, testable unit of work with acceptance criteria.                                         |
| **ADR**                        | Architecture decision record: a short note recording a decision and why.                         |
