# app

`src/app/`

## Purpose

The Preact UI that wires the layers together: loads the instrument, shows a card, reveals it after a delay or on click or key press, advances to the next card, loads the tablature font and shows its license. Drawing is delegated to [`drill`](drill.md); this layer owns input and the timer.

## Public interface

- `App`: loads the alto C instrument, starts loading its font once on mount, and reads `data/settings/defaults.json` at build time through `parseDefaults` ([settings](settings.md)), builds the pool once from its range and sharps flag, and in one `useEffect` creates the card flow with `Math.random` and its delay (`delaySeconds * 1000`), mirrors its state into `useState`, calls `start()` and calls `stop()` on cleanup. The same effect owns input: `click` on `document` and `keydown` on `window` each call `flow.step()` once. It ignores `keydown` with `event.repeat` or Ctrl/Meta/Alt held, and clicks inside an `<a>`, `button`, `input`, `select` or `label` (the license link and the settings controls). It renders a `Card` for the current state and the license footer.
- `createCardFlow({ pool, random, delayMs, advanceDelayMs, onChange })` (`card-flow.ts`, plain TypeScript): returns `{ start, step, stop }` over the state `{ pitch, revealed }`. `start()` draws the first pitch with `drawPitch` and starts the reveal timer. `step()` reveals an unrevealed card and cancels the timer, or, if revealed, draws a different pitch, hides it and restarts the timer from zero; never both. When `advanceDelayMs` is not null, every reveal (timed or by `step()`) starts an advance timer that deals the next card, so the delay counts from the reveal; it is held in the same slot as the reveal timer, so only one timer is ever pending (none for a hidden card's advance). A `step()` on a revealed card deals at once and cancels the advance timer, so it never fires. `null` turns auto-advance off. `stop()` cancels whichever timer is pending.
- `Card({ pitch, revealed, instrument, staffOptions, font })`: presentational. The staff above a fixed-height reveal area. Until revealed the area is empty. When revealed it shows `formatPitch(pitch)` and the [`tabView`](tab.md) of the instrument's glyph for that pitch: the glyph in its font family, or the placeholder message while the font loads or after it fails.
- `Staff({ pitch, options })`: draws the staff with [`drawStaff`](staff.md).
- `startRevealTimer(delayMs, onReveal): () => void`: a `setTimeout` wrapper that returns a cancel function.
- `Section({ title, summary, hasMessage?, initiallyOpen?, children })` (`Section.tsx`): a native `<details class="settings-section">`. Its `<summary>` shows the title and, only while closed, the summary line. The open state is local (`useState`, never stored); `onToggle` runs the browser's state through `sectionOpen` and writes it back, and an effect opens the section when `hasMessage` becomes true. `section.ts` (plain TypeScript) holds `sectionOpen(requested, hasMessage)` (`requested || hasMessage`) and `formatSeconds(n)` (`"3 s"`, `"0.5 s"`). A later feature adds a section with a `<Section>` and no change to the structure.
- `Settings({ instrument, settings, onChange, onClose })`: the settings view: a "Cards" `Section` (open first) and a "Sound" `Section` (starts closed), followed by a Close button in a sticky footer. Two `<select>` pickers (`lowestOptions` / `highestOptions`, labelled with `formatPitch`), an include-sharps checkbox, a reveal delay number input (`min` 0.5, `max` 30, `step` 0.5), an auto-advance checkbox, and an advance delay number input (same bounds; stays enabled when auto-advance is off) make up Cards. Sound holds a "Play note" checkbox, a sound delay input (`min` 0, `max` 30, `step` 0.5) and a sound duration input (`min` 0.5, `max` 30, `step` 0.5), both disabled with their values kept while play note is off. The sharps checkbox is disabled while sharps are on and `canTurnSharpsOff` is false, with the reason from `setIncludeSharps` shown beside it. The auto-advance and play note checkboxes go through `setAutoAdvance` and `setSoundEnabled`; each is disabled while off when turning it on would break the sound sum rule ([settings](settings.md)), with `soundTooLongReason` shown under it. The advance delay and both sound inputs go through `editTiming`; a rejected edit leaves the old value and shows the reason under the edited input, held in local state and cleared by any accepted edit or when the view closes. A section with any of these messages stays open. Every change calls `onChange`, so it is saved with the rest.
- `settings-form.ts` (plain TypeScript): `lowestOptions` and `highestOptions` (the written range below/above the other bound, naturals only when sharps are off, so low is never at or above high) and `cardsSummary` (the Cards summary line, such as `A3 to F5, sharps, reveal 3 s, advance 3 s`; `naturals` with sharps off, `advance off` with auto-advance off) and `applyDelayInput` / `applyAdvanceDelayInput` (the new reveal or advance delay only when finite and in 0.5 to 30, otherwise the settings unchanged; they share one check), `soundSummary` (`on, after 0.5 s, for 1.5 s` or `off`) and `editTiming(settings, field, value)` for `TimingField` (`soundDelaySeconds`, `soundDurationSeconds` or `advanceDelaySeconds`): out of bounds or not finite gives the settings unchanged and `rejected: null`; in bounds goes through `setTimings` and returns its reason as `rejected` when the edit would break the sum rule. Sharps changes go through `setIncludeSharps` in [settings](settings.md).
- `settings-store.ts`: `SETTINGS_KEY` (`fingerwise.settings`), `browserStorage()` (`window.localStorage` or null when absent or blocked), `loadSettings(storage, instrument, defaults)` (defaults on null storage, missing key, throwing `getItem` or bad JSON, otherwise `validateSettings`; never throws) and `saveSettings(storage, settings)` (one `setItem` of `toSettingsJson`; no-op on null, swallows a throwing `setItem`). Storage is injected as `Pick<Storage, "getItem" | "setItem">`. `App` loads the initial settings once into `useState` and builds the pool and delay from them. See [data-formats](../data-formats.md#storage).
- `fontUrl(fileName)`: the built URL of a font in `data/fonts/`, found by file name with `import.meta.glob`, so the instrument JSON's `tablature.font` picks the font. Throws if missing.
- `loadFont(family, url, env): Promise<"loaded" | "failed">`: adds a `FontFace` to `env.fonts` and waits for it. `env` (`{ FontFace, fonts }`) is injected so it runs in Node tests. Never rejects.

- `registerServiceWorker({ navigator, isProd, baseUrl })` (`register-sw.ts`, plain TypeScript): in production and when `navigator.serviceWorker` exists, calls `register(`${baseUrl}sw.js`, { scope: baseUrl })`. A rejected or throwing call is swallowed, so the app runs without a worker. It never skips waiting, shows UI or reloads. `main.tsx` calls it after `render` with `navigator`, `import.meta.env.PROD` and `import.meta.env.BASE_URL`. See [deployment](../deployment.md#service-worker-and-updates).

## Settings view

`App` holds `settings` and `open` in state. A Settings button is shown on every card (in the in-flow header beside the title, so it never covers the staff and does not move it; the header holds only the title while the view is open). Opening clears the card and sets `open`; the card is not rendered while the view is open. The card-flow effect runs only while `open` is false and is keyed on `[settings, open]`: opening runs its cleanup (`flow.stop()`, listeners removed), so the timer stops and clicks and keys no longer drive the card. Closing re-runs it with a pool, reveal delay and advance delay (`settings.autoAdvance ? settings.advanceDelaySeconds * 1000 : null`) built from the current settings, so `start()` draws a new card with a fresh timer. Each change goes through `changeSettings`, which sets the state and calls `saveSettings(browserStorage(), next)`. A stored value is only written when the player changes something.

## Settings sections

The settings controls are grouped into collapsible `Section`s. Cards opens first (`initiallyOpen`); any section added later starts closed. A section with a message to show (today the sharps-blocked note) cannot be closed and opens by itself when the message appears. Open state is not stored, so each time the view opens it starts that way. A closed `<details>` hides its controls from the tab order, and Enter or Space on its summary toggles it natively.

## Layout

All layout is CSS in `app.css`; no JS sizing.

- **Viewport and touch:** `index.html` uses `viewport-fit=cover` and does not disable zoom. `html, body` set `touch-action: manipulation` (no double-tap zoom, pinch kept). `body` has no margin.
- **Safe areas:** `main` pads `max(1rem, env(safe-area-inset-*))` on all four sides, with `box-sizing: border-box` and `min-height: 100dvh`. Nothing hides `overflow-x`.
- **Header:** `.app-header` is a flex row (title left, Settings button right) in normal flow, so the button cannot overlap the card.
- **Card and staff:** `.card` is centered with `max-width: 28rem`. [`drawStaff`](staff.md) sets a view box, so the `.staff` wrapper sizes the SVG: 100% wide up to 220 px, up to 440 px from 600 px wide, with `aspect-ratio: 220 / 150` so the box depends only on viewport width, never on `revealed`.
- **Reveal area:** fixed height per breakpoint (12rem, 15rem from 600 px, 9rem when the viewport is 480 px high or less), so revealing never moves the staff. The placeholder uses the same box as the glyph.
- **Scrolling:** vertical only. No `100vh` heights; a short landscape phone scrolls if it must.
- **Touch targets:** buttons, `<select>`s and number inputs have `min-height` and `min-width` of 44 px and a 16 px font (no focus zoom on mobile). Checkboxes are 1.5rem inside a label row at least 44 px tall.
- **Settings view:** `.settings` is 100% wide up to 24rem; selects and number inputs are capped at 10rem with `min-width: 0` so label text wraps instead of overflowing at 360 px.
- **Settings sections and footer:** `.settings-section` summaries are at least 44 px tall with a pointer cursor; the label rows inside keep their flex layout. `.settings-footer` is `position: sticky; bottom: 0` with an opaque `Canvas` background, in flow after the sections, so it takes its own space at the end of the view and covers nothing when scrolled to the bottom. `html { scroll-padding-bottom: 4rem }` scrolls a focused control or message clear of it.
- **Footer:** wraps (`overflow-wrap: anywhere`) inside the page width.

## Font and license

The font loads on page load, not at reveal, so it is usually ready when the delay ends. The family name is the file name without its extension ([tab](tab.md)). `vite.config.ts` sets `build.assetsInlineLimit` so files under `data/fonts/` are emitted as files, never data URIs. `dist/assets/` holds the `.ttf` and `OFL-*.txt`, and the footer links the license. No font request goes to another host. See [`data/fonts/README.md`](../../../data/fonts/README.md) and [ADR 0002](../decisions/0002-tablature-from-panzi-font.md).
