# app

`src/app/`

## Purpose

The Preact UI that wires the layers together: loads the instrument, shows a card, reveals it after a delay or on click or key press, advances to the next card, loads the tablature font and shows its license. Drawing is delegated to [`drill`](drill.md); this layer owns input and the timer.

## Public interface

- `App`: loads the alto C instrument, starts loading its font once on mount, and reads `data/settings/defaults.json` at build time through `parseDefaults` ([settings](settings.md)), and in one `useEffect` creates the flow for the mode (F16): in Song mode with Single note a [single note flow](#single-note-practice), with Tempo the timed flow (see below); in Flashcards always (AC9) the card flow with a pitch source and its delay, `randomSource(poolFor(settings), Math.random)` with the saved song ignored, or, when `smartSamplingApplies(settings)` ([settings](settings.md)), `needSource(poolFor(settings), () => scoresRef.current, Math.random)`. `scoresRef` is a `useRef<Scores>` loaded once at mount with `loadProgress(browserStorage(), instrument)`, so scores from before a reload are used; it is a ref, not state, because a grade must not re-run the flow effect and deal a new card. When smart sampling applies the flow gets `onGraded`, which sets `scoresRef.current = applyGrade(scoresRef.current, pitch, grade)` and then calls `saveProgress(browserStorage(), instrument, scoresRef.current)` at once; otherwise `onGraded` is null, so nothing is graded or written. A song is never drawn from the pool, drawn by need or graded. While the mode is Song and no song is held yet (the load-time parse is running), no flow starts and no card shows. The song is a dependency of the effect, so closing the settings view starts at the first note. The flow's delay is `delaySeconds * 1000`. The effect mirrors the flow's state into `useState`, calls `start()` and calls `stop()` on cleanup. The same effect owns input: `click` on `document` and `keydown` on `window` each call `flow.step()` once. In Tuner (F19) the flow is the [tuner flow](#tuner). It ignores `keydown` with `event.repeat` or Ctrl/Meta/Alt held, and clicks inside an `<a>`, `button`, `input`, `select` or `label` (the license link and the settings controls). The effect also passes the tone when `settings.soundEnabled`: `delayMs` is `soundDelaySeconds * 1000`, `play(p)` calls the tone player with `soundingPitch(instrument, p)` and `soundDurationSeconds`, `stop()` stops it; with play note off the tone is null. A module-level `audio = createAudio(browserAudioFactory())` and `player = createTonePlayer(audio)` are the app's one audio context and player ([audio](audio.md)). A mount-only effect adds `click`, `keydown` and `touchend` listeners on `window` with `{ capture: true }` that call `player.unlock()`, so the unlock runs before `flow.step()` on the same gesture; they are removed on cleanup. Opening the settings view runs the flow effect's cleanup, whose `flow.stop()` cancels a pending tone and stops a playing one. Nothing extra is shown when audio is unavailable. A module-level `listener = createListener(audio, browserListenerEnv())` shares that context ([audio](audio.md)). With `settings.judgeEnabled` the effect passes `listen` (see [Listening](#listening)): a fresh `createToneTracker({ ...DEFAULT_THRESHOLDS, band: frequencyBand(instrument) })`, `grade: (p, hz) => judge(soundingPitch(instrument, p), hz, settings.toleranceCents)` and `now: () => performance.now()` ([judge](judge.md)); with judging off `listen` is null. It renders a `Card` for the current state and the license footer.

With `showOpenFilePicker` (Chrome and Edge on desktop; declared locally as `FilePickerWindow`, since TypeScript's DOM types lack it) it calls it with `PICKER_OPTIONS`: `id: "fingerwise-song"`, `multiple: false` and the `.abc` and `.txt` types; the browser keeps the folder for that id, so the next press starts where the last file came from (a page is never told a path, so the app keeps none). Both the window and the input are injectable for the tests.

F18-S02: `tuneTempo(song)`, `tempoEntries(song)`, `chosenTempo(song, songTempo)`, `withTempo(song, tempo)`, `tempoChoice({ settings, song, open, phase })` and `chooseTempo(settings, song, index)` (see **Tempo list**). `PLAY_SONG_TEXT`, `STOP_TEXT` and `playButton({ settings, song, open, webAudio, playing, phase })` (see **Play song**). `App` renders them in the header. - `type PitchSource = (previous: Pitch | null) => Pitch` and `randomSource(pool, random)` (`card-flow.ts`): where a card's pitch comes from. `randomSource` is `drawPitch` over the pool (never the same pitch twice in a row, unless the pool is one pitch). F16-S02 removed `songSource` and the drill's `nextInOrder`: no flashcard follows a song's order.
- `createCardFlow({ next, delayMs, advanceDelayMs, retryAdvanceMs?, tone?, listen?, onChange })` (`card-flow.ts`, plain TypeScript): returns `{ start, step, stop }` over the state `{ pitch, revealed, verdict, listening, retry }`. `retry` (F18-S03) is `listening` while a missed card waits to be played right, `right` once it was, and null outside a retry (see [Listening](#listening)). `verdict` is null while hidden and a `Verdict` once revealed: `{ grade: "correct" | "incorrect", frequency }` from the judge, or `{ grade: "none" }`. `listening` is `off`, `opening`, `locked`, `running` or `unavailable`. Without `listen` every reveal has `none` and `listening` is `off`, and the flow is exactly as below. `start()` takes the first pitch from `next(null)` and starts the reveal timer. `step()` reveals an unrevealed card and cancels the timer, or, if revealed, takes the next pitch from `next`, hides it and restarts the timer from zero; never both. When `advanceDelayMs` is not null, every reveal (timed or by `step()`) starts an advance timer that deals the next card, so the delay counts from the reveal; it is held in the same slot as the reveal timer, so only one timer is ever pending (none for a hidden card's advance). A `step()` on a revealed card deals at once and cancels the advance timer, so it never fires. `null` turns auto-advance off; `retryAdvanceMs` (F18-S03; `App` passes `advanceDelaySeconds * 1000` with auto-advance off, else null) is then the advance delay after a card played right. `stop()` cancels whichever timer is pending. The optional `tone` (`CardTone { delayMs, durationMs, play(pitch), stop() }`, null or absent for silence) sounds the note on every reveal, timed or by `step()`: with `delayMs` 0 `play` is called synchronously inside the reveal (so it runs on the input gesture), otherwise a separate sound timer starts at the reveal; a hidden card has none. Dealing the next card (a `step()` or the advance timer) and `stop()` cancel the sound timer and call `tone.stop()`, so the advance stops the tone even when delay plus duration equals the advance delay. A throwing `tone.play` or `tone.stop` is swallowed. `needSource(pool, scores, random): PitchSource` (F06-S04) is `drawWeighted(pool, previous, p => drawWeight(scores(), p), random)` ([drill](drill.md), [progress](progress.md)); it reads `scores()` on every draw, so a grade applied since the last card counts, and scores for pitches outside the pool are untouched. The optional `onGraded(pitch, grade)` is called at most once per card, from `reveal()` right after the revealed state is shown, only when `listen` is set and the card's `listening` is `running`: `correct` for a correct verdict, `miss` for an incorrect one or `none` (a timed reveal or a tap). It is not called for `opening`, `locked`, `unavailable` or `off`, and a throwing `onGraded` is swallowed like `tone`. The optional `listen` (`CardListen { listener: { start, stop }, tracker: { reset, push }, grade(pitch, hz), now() }`) judges each card before its reveal; see [Listening](#listening).
- `Card({ pitch, revealed, listening?, judging?, verdict?, retry?, instrument, staffOptions, font })`: presentational. The staff above a fixed-height reveal area; `judging` (from `settings.judgeEnabled`, not from `revealed`) adds the `.judging` class, which gives it a taller fixed height. Until revealed the area is empty, except for a `.card-status` line: `LISTEN_PROMPT` ("Tap or press a key to start listening") while `listening` is `locked`, and `JUDGE_UNAVAILABLE` while it is `unavailable`. The texts are in `judge-text.ts`, shared with `Settings`. When revealed it shows `formatPitch(pitch)` and the [`tabView`](tab.md) of the instrument's glyph for that pitch: the glyph in its font family, or the placeholder message while the font loads or after it fails. With `judging` and a verdict (and listening not `unavailable`), a verdict row follows: an icon (`✓`, `✗` or `–`, `aria-hidden`) and a text label (Correct, Incorrect, Nothing heard) in a class per grade (`verdict-correct`, `verdict-incorrect`, `verdict-none`), so color is never the only signal; with `retry` `right` (F18-S03) the label is `RETRY_RIGHT` ("Right, counted as a miss") with the same ✓ icon and `verdict-correct` class. For correct and incorrect the row also holds the judged note (`judgedNote(...).label`, such as `C♯5 +23¢`) and a `PitchGraph` follows; for `none` nothing more. A song card (`song` set, F10-S03) renders `.song-bar` instead of the reveal area (see Layout). Single note (F16-S02) passes `single { ended, fingering }`: with `fingering` the card builds `song.fingering` from `pitch` (`formatPitch` and the instrument's glyph through `tabView`) for the strip, and with `ended` the bar reads `END_OF_SONG` ("End of song"); there is no start prompt, and `timed` is undefined so the scroll lock stays off. Judge off renders exactly as after F03.

When `tempoApplies(settings)` ([settings](settings.md)) and a song is held, the flow effect builds a timed flow instead of the card flow: no tone, no reveal or advance delay, and the card flow's code is not touched. `App` keeps a `timed` state beside `card`; a card and a timed song never show together. The flow's clock is `clicker.now()` (the audio clock), falling back to `performance.now() / 1000` with no context, so a song without audio runs silent but in time. Clicks and keys call `step()` as they do for the card flow (the capture-phase unlock runs first). The page-visibility key also applies to a timed song with judging off, so hiding the page, opening Settings or changing a setting stops it and its clicks, and showing the drill again shows the first note with the start prompt.

`timed-flow.ts` (plain TypeScript): `createTimedFlow({ song, clock, clicker, metronome?, listen?, outputLatency?, onChange })` with `start()`, `step()` and `stop()`; `LEAD_SECONDS` (0.1), `METRONOME_LOOKAHEAD_SECONDS` (1), `INPUT_ALLOWANCE_MS` (55), `FALLBACK_LAG_MS` (100) and `scoringLagMs(outputLatency)`. State `TimedState { index, pitch, beats, phase, countBeat, listening, summary, analysis }`, where `index` is the shown note's index in the song and `beats` its length, phase `ready | count-in | playing | summary`, and `countBeat` the count-in beat clicking (0 from `t0`, one more each `beatMs`), null before `t0` and outside the count-in. `start()` shows the first note in `ready`. `step()` in `ready` or `summary` starts the count-in: `t0 = clock.now() + LEAD_SECONDS`, one click per `countIn(meter, tempo)` beat from `t0`, and the first slot at `t0 + beats * beatMs / 1000`; in `count-in` and `playing` it does nothing. Slot boundaries are absolute times, the first slot's start plus the cumulative sum of `songSlotsMs`, never a delay added to the last. One `setTimeout` waits for `boundary - clock.now()` (rounded up); when it fires before the clock reaches the boundary (a resuming audio context's frozen clock) it re-arms, so a card never shows early and the song cannot drift from the clicks. One scoring lag after the last slot ends the phase is `summary`, with the [coverage](coverage.md) result as `summary` (see below); until then the last note stays shown in `playing`. A step starts the count-in again with a fresh scoring. `stop()` cancels the timer, calls `clicker.stop()` and releases the microphone. A null clicker keeps it silent but in time. With `metronome` on (`App` passes `metronomeApplies(settings)`), clicks continue the count-in's beat grid: one at the first slot's start and every `beatMs` after it, for every beat strictly before the last slot's end, so there is no gap or double at the first slot. They are scheduled a batch at a time: at the count-in for the first slot plus the lookahead, and at each slot start for the beats up to that slot's end plus the lookahead. Nothing is scheduled once the summary shows; `stop()` and a restart call `clicker.stop()` first, so a restart starts a clean grid. The pickup of a tune is not placed on the bar lines. `Card` takes `timed` (`ready`, `playing`, `summary`) and `timedSummary`: the reveal area holds only `START_PROMPT` ("Tap or press a key to start") in `ready`, nothing while counting in and playing, and the summary text and the tuning line (see **The summary** below); no letter or tablature shows. Instead of one note the staff shows lines of music: `App` memoises `songLines(song, settings.barsPerLine)` and passes `Card` a `song` view (`{ lines, meter, barsPerLine, current, countBeat }`, where `current` is `timed.index`, or -1 in `ready` and the count-in so every note is grey; `countBeat` is the flow's, 0 until the first click, so the first rest is lit while waiting for the tap, and null once playing); `Card` then renders `SongStaff` (`Staff.tsx`), which calls `drawSongLines` ([staff](staff.md)), and takes the `card-song` class, which widens the card to 56rem. `SongStaff` draws the staff only when `lines`, the options, the meter or `barsPerLine` change; on a change of `current` or `countBeat` it calls `colourSong`, so a note change never redraws VexFlow. Its `song-staff` box is `position: relative` with an `aspect-ratio` set from the whole drawn view box, so the card grows with the song.

**The lane** (F09-S04): a timed song's card draws a lane under each staff row, with judging on or off (random and untimed song cards use `Staff` and are unchanged). `App` builds `buildTimeline(song, tempo)` (the song's tempo or `DEFAULT_TEMPO`) and passes it and the tempo in the `song` view. `lane.ts` (plain TypeScript): `laneSegments(timeline, lines, layout, tempo)` gives `{ row, x0, x1, kind: "note" | "rest", graded, index, starts, ends }` (`row` an index into the layout's rows) for every note and rest on each row, clipped to the row's beats and turned into x by `rowMap(...).span` (the timeline's ms times tempo over 60000 for beats). A rest spans its written length; a note, graded or not, runs from its start to where its release starts (`endMs - releaseMs`, [ADR 0011](../decisions/0011-release-allowance.md), F15-S03), so nothing neutral is drawn in the release and it looks like the gap between segments; a note slurred into the next has no release and keeps its full length, and a note with no length left is skipped. `ends` therefore means the segment holds the release start. A note tied over a bar line is one continuous segment and a note over a line break has one on each row, except that a row holding only the release gets no segment; the count-in bar has none. The same private row walker gives `laneNoteEnds(timeline, lines, layout, tempo): NoteEnd[]` (`{ index, row, x }`), each note's written end on the row that holds it, which the ended-late and not-separated marks need even where no segment reaches it. Judging off draws the same segments, so they are shortened too. `SongOverlay.tsx` is an SVG over the staff with the same view box (`pointer-events: none`, `aria-hidden`): one `<path>` of rectangles for graded segments (`.lane-graded`, neutral grey) and one for ungraded ones (`.lane-ungraded`, lighter), each rectangle running from the row's `laneTop` to `laneBottom` with a 1-unit gap between neighbours. It is rebuilt when the layout changes and holds no per-frame state. `SongStaff` draws the whole song once (its draw effect depends on the lines, options, meter and bars per line only, so a resize or rotation scales the SVG by CSS and redraws nothing, and every row keeps its lane, fill and marks); the card grows with the song through the box's `aspect-ratio` from the whole layout (F10-S02).

**The playhead** (F09-S05): `TimedState` gains `origin`, the flow clock's seconds at the first note's start (set in `run()`, null in `ready`). `playhead.ts` (plain TypeScript): `playheadBeat(clockNow, outputLatency | null, origin, tempo)` is the time the player hears in beats, `(clockNow - (outputLatency ?? 0) - origin) * tempo / 60`, negative during the count-in; the clock is the audio clock, or the page clock when there is no audio (the flow's fallback), with no latency then. `playheadPlace(beat, rows)` gives `{ row, x }` (an index into the layout's rows, every row of the song): a row holds the beats from its first stop to its last (its end bar line), so a beat at the end of a line is on the next row at its first note, and the playhead moves to the start of that row; before the first row it waits at its start and past the last at its end; x comes from `rowMap(...).beatToX` over the row's stops without the bar lines that share a beat with the next bar's first note (otherwise the line would run to the bar line and jump across the gap to the note when the beat arrives; it now glides over it, a little faster there), so it is at each note's x when the note is due, and runs through the count-in bar's rests in time with the clicks. (The story's `lineOf` argument is not needed: the rows carry their stops.) `SongOverlay` holds one `<line class="playhead">` across the current row and its lane (`top` to `laneBottom`). While the song's `playhead.running` (phase `count-in` or `playing`, with an origin) one `requestAnimationFrame` loop sets the line's `x1`, `x2`, `y1` and `y2` from `playhead.now()` and `playhead.outputLatency()` (`outputLatencySeconds(audio)`), with no Preact state and no VexFlow. The loop is cancelled by the effect's cleanup when the song stops running (the summary), when the layout changes (restarted at once) and when the overlay unmounts (Settings, judging toggled, page hidden all remove or rebuild the flow); a restart from the summary starts it again from the count-in. `overlayRun(running, origin)` (F18-S01) gives `"run"` while running with an origin, `"keep"` with an origin and not running (the summary keeps its fill, marks and stopped line) and `"clear"` with no origin (a fresh flow in `ready`). At the summary the line stays where it stopped. The playhead is not pulled back by the scoring lag, and the note to play is still black.

**Following the song** (F10-S04): `follow.ts` (plain TypeScript, no Preact): `FOLLOW_FRACTION` (1/3) and `SCROLL_MS` (450, a first guess); `followTop({ rowTop, viewport, header, bar, maxScroll })` is `rowTop - header - FOLLOW_FRACTION * (viewport - header - bar)` clamped to `[0, max(0, maxScroll)]`, so the first and last lines sit where the page allows and a song that fits never scrolls; `easeInOut(t)`; `createScroller({ scrollY, scrollTo, now, frame, cancelFrame })` with `to(top, smooth)` (a smooth move tweens from the current position over `SCROLL_MS` by animation frame, a new `to` restarts from where the page is, a jump cancels any tween, a target equal to the position does nothing) and `dispose()`. `SongOverlay` takes `onRow(row)`, called from its frame loop when the playhead's row differs from the last one reported (reset at each loop start, so a run's first frame reports row 0 during the count-in); following the playhead, not the current note, starts the scroll as the playhead reaches the line even when it opens with a rest or a tie carries over the break. `SongStaff` (props `phase`, `header`, `bar`; `Card` passes its `timed`, its bar ref and `App`'s header ref) owns one scroller over `window` per mount, disposed on unmount. On a row it measures afresh: the row's top in page pixels (`box.getBoundingClientRect().top + scrollY + row.top * clientWidth / layout.width`), the header and bar `offsetHeight`, `innerHeight` and `scrollHeight - innerHeight`, and scrolls smoothly unless `(prefers-reduced-motion: reduce)` matches. A window `resize` while the playhead runs jumps (no tween) to the last row's target. When `phase` becomes `ready` the page jumps to the top, which also cancels a tween. **Live fill and readout** (F09-S06): `TimedFlow` exposes `progress()`, the coverage run's `Progress` (null when nothing is scored and after the summary), and `reading()`, the newest raw microphone reading. `trace.ts` (plain TypeScript): `traceY(cents, laneTop, laneBottom)` maps `±TRACE_SPAN_CENTS` (150) linearly onto the lane, sharp upwards, clamped to the edges; `traceColour(cents, tolerance)` is `green` within the tolerance, `amber` up to ±50 and `red` beyond; `segmentPaths(segments, rows, tempo, tolerance)` returns, for each row, one path string per colour of filled rectangles (`LaneRow`s from `laneRows(lines, layout)`: a row's beats, its `rowMap` and its lane). On a note each sounding reading of a segment is a `TRACE_THICKNESS` (3) line from its time to the next reading's (or the segment's end), at its offset's height and colour, kept inside the lane; a wrong reading is drawn at its offset within the span and, beyond it, pinned to an edge and red (it is beyond ±50, so red either way); silence on a note draws nothing, leaving the neutral lane. On a rest, silence is a green band (`REST_BAND`, 8 units) across the lane's middle and sound a red one. Notes and rests too short to grade are never filled. Segments are placed at song time, so the fill trails the playhead by about the scoring lag. `SongOverlay` has, per row of the song, a settled and an open `<path>` for each colour, and a path of faint dashed guide lines at ±tolerance and ±50 cents. Its frame loop (the playhead's) reads `progress()` through `FillSource` (`App` gives module-level `fillProgress` and `fillReading`, which follow the active flow): a new `segments` array (a new run) clears everything; segments finished since the last frame are appended to the settled paths and never recomputed; the open ones are redrawn each frame, and only when their path changed, and only on the rows `rowsToUpdate(rows, playheadRow, open, tempo)` (`trace.ts`) names: the playhead's row plus every row an open segment reaches by beat range (so just after a line break, the row before too). A row that leaves that set has its open paths emptied once. Settled fill and marks are written only to rows that got something new, and are never cleared when play moves on, so every row shows its fill and marks, also in the summary. A new run clears every row. With judging off `fill` is null: there is no scoring, so no fill, guides or readout. **Readout:** `Card` renders an empty `<p class="card-status card-readout">` in the reveal area while a timed song's stream is `running` in the count-in or playing (`readout` prop, from `App`); the overlay's loop sets its text node directly, never Preact. `hearingText(instrument, reading)` in `judge-text.ts` is "Hearing " and `judgedNote(...).label` (the nearest written note and its offset from it, so 62 cents sharp of D4 reads "Hearing D♯4 -38¢"), or `HEARING_NOTHING` ("Hearing nothing") when the reading fails the judge's checks with the instrument's band. `createReadoutThrottle()` returns a function that allows one change per `READOUT_INTERVAL_MS` (100): a change to the text is shown only when it says yes.

**The playback view** (F13-S03): while `playing` and `playback` are set, `App` renders one `Card` in either practice: the first note's `pitch`, `revealed` false, `timed="playing"`, `timedNote` `PLAYING_SONG` ("Playing the song", in `judge-text.ts`, the card's quiet line in the pinned bar), no legend, no readout, `judging` false, and `song` from `playbackView`. `PlaybackState.index` is the sounding note: 0 through the count-in, each note's index from its start, and -1 from the written end of a note followed by a rest until the next note starts. Repeated and slurred notes change at the next start with no grey between, and the tone's release (it stops where the note's release starts, [ADR 0011](../decisions/0011-release-allowance.md)) is not shown: the sounding note stays highlighted to its written end. `soundingChanges(song, tempo): { atMs, index }[]` (pure, in `playback-flow.ts`) lists these changes in time order; the flow arms its clock timer at each, emits `playing` with the new index, and sends a tone and beat batch at each change. `playback-view.ts` (plain TypeScript, type-only import of `SongView`): `playbackView(base, state, clocks)` takes `lines`, `meter`, `barsPerLine`, `timeline` and `tempo` and sets `current: state.index`, `countBeat: null`, `playhead: { running: true, origin: state.origin, now, outputLatency }` (so the playhead is placed as in a run: the flow's `origin` equals the timed flow's), `lanes: false`, `fill: null`, `after: false`, `scored: null`, `spots: []` and `overrun: null`. `SongView.lanes` (default true) goes to `SongOverlay`, where `show = lanes && (!after || scored !== null)`: with `lanes` false no lane, guide, fill or mark path is drawn, while the playhead line still moves and the frame loop still reports rows, so the page follows line by line. `Card` locks scrolling for a song in `playing`, which the playback card is; on the end or Stop the card unmounts, which lifts the lock, and the timed card mounts in `ready` (which jumps to the top) or the untimed card shows.

`clock-timer.ts` (plain TypeScript): `createClockTimer(clock)` with `at(time, action)` and `cancel()`, and `CLOCK_EPSILON`: one timer slot, `at` replaces any waiting action, and a timer that fires before the clock reaches `time` re-arms. `timed-flow.ts` and `playback-flow.ts` share it. `playback-flow.ts` (plain TypeScript): `createPlaybackFlow({ song, clock, clicker, tones, sounding, metronome, onChange, onEnd })` with `start()` and `stop()`, and `PlaybackState { phase: "count-in" | "playing"; index; origin }`. `start()` takes `t0 = clock.now() + LEAD_SECONDS`, clicks one count-in bar as the timed flow does (`countIn(meter, tempo)`, a pickup still getting the whole bar), and puts the first note at `t0` plus that bar (`origin`), emitting `count-in`. Each tone of `playbackSchedule(song, DEFAULT_TEMPO)` goes to `tones.schedule(sounding(pitch), origin + startMs / 1000, lengthMs / 1000)`. With `metronome`, a click falls on every beat of the grid from `origin` strictly before the last written end; without it there are none after the count-in. Tones and beats go out in batches: at `start()` up to the first note's start plus `METRONOME_LOOKAHEAD_SECONDS`, and at each sounding change (see below) through the clock timer, up to the next change (or the end) plus the lookahead. So a note or rest longer than the lookahead never leaves a beat unsent until it is due, which Web Audio would play at once, stacked on a later click. The first note's start emits `playing`, and `onEnd` is called once at the last note's written end. `stop()` cancels the timer, calls `clicker.stop()` and `tones.stop()`, and nothing more is emitted, scheduled or ended; a second `stop()` is harmless. Null `clicker` or `tones` keep it silent but in time.

**Listening past the end** (F12-S03): with `after` and a running scoring, the song does not end one lag after the last slot. `overrun.ts` (plain TypeScript) has `createSilenceWatch()` with `push(timeMs, sounding)` and `silentMs()`: the song time from the first non-sounding reading after the last sounding one to the newest reading (from the first reading when nothing has sounded; 0 with no readings or while the newest one sounds). Every reading in song time goes to the watch, sounding when `passesChecks(reading, listen.coverage.checks)` ([judge](judge.md)), the core's own silence test. Two constants in `timed-flow.ts`: `OVERRUN_SILENCE_MS` (1000) and `OVERRUN_CAP_MS` (10000). The stop rule: at the last slot's end `TimedState.overrun` becomes true (the phase stays `playing`, so the scroll lock and the following are unchanged) and the flow waits one scoring lag; then it summarises at once when `silentMs()` is at least `OVERRUN_SILENCE_MS`, otherwise it re-arms its one timer for `OVERRUN_CAP_MS` later and lets each reading check the watch, summarising (once: `summarise()` guards against a second call) as soon as the silence is long enough. Time comes only from the readings, so a stalled frame loop cannot end the run early. Readings and level blocks whose song time is after the last slot's end (the last note's end) are not fed to the coverage run, so the result is what it would be without them; the readings are kept on the scoring instead and handed over as `TimedState.overrunReadings` with the summary (empty in every other state, and without `after`). `stop()` and a restart drop the kept readings and the watch with the scoring, so a stop during the overrun judges nothing. The metronome is scheduled only before the last slot's end, so nothing clicks in the overrun. `App` passes `timedNote` `LISTENING_PAST_END` ("Listening… stop playing to see your score") while `overrun` is true, else `SCORING_AFTER`. Without `after`, or with no scoring, the end is as before.

**The overrun lane** (F12-S04): with scoring after the song, what was played after the last note gets its own short lane under the last line. `overrun.ts`: `overrunTrace(readings, checks, startMs)` turns `TimedState.overrunReadings` into `{ points, endMs }`: the readings that pass the checks (`CHECKS`, the judge's defaults with the instrument's band), each `{ timeMs, endMs, cents }` with the times in ms after `startMs` (the timeline's last note end), `cents` from `nearestPitch(frequency)` and `endMs` the next reading's time (its own for the last reading); the trace's `endMs` is the last point's end; null when nothing sounded, so no lane and no line. `overrunLane(lastRow, layoutHeight, trace, tempo, tolerance)` gives the figures in the overlay's view box: the lane starts at the last row's first x (left-aligned with that row's lane) under the layout, below a small label band, as tall as the row's lane, on the row's average scale (its width over its time, so time zero is the last note's end); `paths` holds one `TRACE_THICKNESS` rectangle per point at `traceY` in `traceColour`, `guides` the lines at the tolerance and the right-note band both ways, `extraHeight` is the height to add to the view box, and `more` is the ms of the trace past the row's width (points are cut there, those wholly past it dropped) or null, shown as `overrunMoreText` ("+3.2 s") right-aligned in the label band. `App` memoises the trace only in the summary with scoring after the song and lanes shown, passes it in the `song` view as `overrun` and its `endMs` to `Card` as `timedOverrunMs`; a restart empties `overrunReadings`, so both go. `SongStaff` builds the lane from the last `LaneRow`; a separate effect sets the box's `aspect-ratio` to `width / (height + extraHeight)` so the staff is not redrawn and the music, a top-aligned block, does not move, and the box stays in flow above the sticky bar so the lane scrolls clear of it. `SongOverlay` takes it as `overrun`, extends its view box and draws the lane rectangle (`.lane-graded`), its guides, the three fill colours and `<text class="overrun-label">` "after the end" (`OVERRUN_LABEL`, with the spot label's halo). [staff](staff.md) is unchanged. The analysis gets one more habit line, `overrunText(ms)` ("You played 3.2 s past the end", one decimal), added by `Analysis.tsx` after the drift line (and under the habits heading when it is the only one); it is app text, not a field of [analysis](analysis.md). No coverage, timing, separation or tuning figure changes: the readings never reach the run.

**Fault marks** (F09-S07): the core's `progress()` reports each `TimingFault { index, edge, kind }` and each not-separated `JoinFault { before, after, atMs }` as its note finishes, in arrays that only grow; a note with no right-note time has no edges and so no fault, and slurred joins are never checked, so they are never reported. `laneSegments` now marks each segment `starts` and `ends`: whether it holds the note's own start or end, or only a continuation across a line break. `marks.ts` (plain TypeScript): `faultMarks(faults, joins, segments, ends)` gives `{ row, x, shape }`, where `shape` is `start-early`, `start-late`, `end-early`, `end-late` or `not-separated`. A start mark sits at the start (`x0`) of its note's segment; an ended-early mark at the end (`x1`) of the segment that holds the release start, where it was measured; an ended-late mark at the note's written end (its `NoteEnd`); a not-separated join at the written end of the note before it (its `NoteEnd`), also between two notes of the same pitch, or at the start of the note after when only that row has it. A fault whose edge is on no row gives no mark. `Staff.tsx` memoises `laneNoteEnds` beside the segments and passes it to `SongOverlay` (`ends`), whose frame loop and `settledPaths(scored, segments, ends, rows, tempo, tolerance)` pass it on; the fill and trace still use the coverage segments, which cover the whole note, so the trace shows in the release. `markPath(mark, laneTop, laneBottom)` draws a timing mark in the lane's top quarter, above the trace's centre line: a thin tick on the edge and a small triangle inside the note beside it, pointing left for early and right for late, so the four are told apart by which edge and which way the pointer faces, not by colour; a not-separated mark is a thin slur (a crescent, like the curve of a tie) under the join, in the lane's bottom quarter: the notes run together. All are one dark colour (`.lane-marks`, filled and stroked). `SongOverlay` has one `<path>` per row for them: its frame loop appends the faults and joins reported since the last frame (it remembers how many of each it has drawn, and starts again when the run's arrays change), so each appears when the core finishes the note, with the fill, and a new run clears them. **Legend:** `Legend.tsx` is a key under a timed song's staff while judging is on: a list of the five marks, each drawn by `markPath` in a small SVG beside its label (`MARK_LABELS`: "Started late", "Started early", "Ended early", "Ended late", "Not separated"), so the key and the lane cannot drift apart. It is part of the card's fixed layout, so the card does not change height as the song runs. A "Bars per line" number input (1 to 4) follows "Metronome" in the Song section, disabled unless keep tempo applies; `applyBarsPerLineInput` in `settings-form.ts` ignores anything but a whole number in range. Untimed song cards also draw their note's length; random and need cards draw a whole note.

**The summary** (F09-S08, replacing S03's interim "N% covered"): both texts are in `judge-text.ts`. `summaryText(result)` builds, from the coverage result and joined with " · ", "N% covered", "M% in tune", "started late a%, early b%", "ended early c%, late d%", "not separated e%" and "K notes too short to grade" (singular "1 note"), for example "82% covered · 64% in tune · started late 12%, early 3% · ended early 5%, late 20% · not separated 10% · 2 notes too short to grade". Each percentage is rounded. A part with nothing to count is left out rather than shown as 0%: the in-tune figure when no note was played right, a timing pair when no graded note has that edge (both of a pair share the notes-with-that-edge denominator), separation when there are no plain joins, and the too-short part at zero. A result that graded nothing, or a null result (judging off, a stream that was not running, a failed scoring), gives `END_OF_SONG`, "End of song". `tuningText(tuning)` gives "Furthest off: D4 +70¢ · E5 +40¢ · C4 −35¢" (rounded cents, a true minus sign, at most three pitches in the order the core gave, worst first), or null when the list is empty. `Card` renders the summary and, when there is one, the tuning line as two `<p class="card-status">` in the reveal area in `summary`; they are plain text, so a screen reader reads them, and `.card-status` has `overflow-wrap: anywhere` so a long summary wraps instead of scrolling sideways. A tap in `summary` restarts from the count-in: `run()` makes a fresh coverage run, the state's summary is null again, and the overlay's frame loop restarts with the new origin, clearing the fill and marks. Nothing is stored: `App` passes the timed flow no `onGraded` and it has no storage, so smart sampling (F06) is unaffected; a test runs a scored song, its summary and a restart with the storage globals trapped.

**The analysis section** (F11-S03): `TimedState.analysis` is the [analysis](analysis.md) of the run, computed in `summarise()` after `finish()` from the song, tempo, the `Timeline` the flow keeps on its scoring, `progress().segments` and the result, in its own try/catch (a throw gives null and leaves the summary alone). the habits and spots as lists of plain text. `Card` renders it between `.card-staff` and `.song-bar` when `timed === "summary"` and `timedAnalysis` (`App` passes `timed.analysis` only with judging on) is set, and, in `.song-bar` after the summary and tuning lines, an `<a href="#song-analysis" class="analysis-link">Analysis ↓</a>` (at least 44 px tall). The link shows only while the section's heading is below what can be seen (F11-S05): `Card`'s `useAnalysisBelow` checks `isBelowView(heading bottom, the bar's top)` after the summary renders and on scroll, resize and a `ResizeObserver` on the root, so it is absent on a window that holds the whole page, goes once the heading is in view and stays gone while scrolled further down. Its height changing the bar's top cannot make it flicker, since hiding it only uncovers more of the page. The section is in flow above the sticky bar, capped at the music's width with `overflow-wrap: anywhere`. A restart removes the section with the summary; the existing jump to line 1 and the row-0 follow are unchanged.

**Shaded practice spots** (F11-S04): `App` puts `timed.analysis?.practice.spots` into the `song` view's `spots` only in the summary with judging on, so a restart (analysis null) empties them. `SongOverlay` takes `spots` and draws first in its SVG, so it sits under the lane, fill, trace and marks, one `<rect class="practice-spot">` per row part from `beatRangeOnRows(layout.rows, startBeat, endBeat)` ([staff](staff.md)), from the row's `top` to `laneBottom`. **Coverage scoring in timed songs** (F09-S03, replacing F08's per-slot grading): with judging on, `App` passes `timedListenFor(settings)`, a `TimedListen { listener, coverage }` whose `coverage` is the [coverage](coverage.md) options (the tolerance setting, `{ ...DEFAULT_THRESHOLDS, band }` and `soundingPitch` of the instrument), and `outputLatency: () => outputLatencySeconds(audio)`; `App` passes no `onGraded`, so nothing is stored and smart sampling (F06) is unaffected. On the start tap the flow calls `listener.start(onReading)` once (a restart reuses the running stream; a `locked` result is asked again) and sets `listening` to `opening`; the count-in starts when the promise settles, whatever the result (a throw or rejection is `unavailable`), and a result after `stop()` is ignored. When `run()` starts the song with `listening` `running`, it builds `buildTimeline(song, tempo)` and a fresh `createCoverageRun`, and reads the scoring lag once: `scoringLagMs(outputLatency())`, which is the input allowance `INPUT_ALLOWANCE_MS` (55 ms, the measured key-tap figure, to be tuned on desktop and Android) plus the context's `outputLatency` in ms, or `FALLBACK_LAG_MS` (100) when it is not reported. Measured on 2026-11-22: Firefox on Linux with the USB headset reports `outputLatency` 0.045 s, a lag of about 100 ms, the same as the fallback; Bluetooth output and Android were not tried, and the constants of the [coverage](coverage.md) module were not changed in the live checks. Every reading from then on, the count-in included, goes to the run in song time: `(audioTime - firstSlot) * 1000 - lag` ms, where `audioTime` is the listener's audio-clock stamp and `firstSlot` the flow clock's seconds at the first slot's start (they are the same clock when there is audio); the reading's `envelope` blocks are placed the same way and pushed first. A reading with no `audioTime` is dropped, and the tone tracker is no longer used in timed songs. The last note's sound reaches the scoring one lag after its slot ends, so the phase stays `playing` on the last note until `songEnd + lag`, then the run's `finish()` result becomes `summary`. With judging off, or a stream that is `opening`, `locked` or `unavailable`, no run is made: the song plays in time, the summary is null and shows `END_OF_SONG` straight after the last slot. A scoring that throws is dropped and leaves the song playing in time with a null summary. No note heads are coloured by result: the staff shows the note to play black and the rest grey, and `Card` shows no verdict row for a timed song. Until the live fill (F09-S06) there is no feedback while playing. The microphone is released as in F04 when the timed song stops (Settings, judging off, page hidden).

The component has no test environment, so the button, the two pickers in a browser and the messages are checked by hand.

## Single note practice

Song mode with the Single note practice (F16-S02) has no clock. `App`'s flow effect, when `singleNoteApplies(settings)` and a song is held, creates `createSingleNoteFlow({ count: song.notes.length, fingeringDelayMs, advanceDelayMs, onChange })` (`single-note-flow.ts`, plain TypeScript, using `startRevealTimer`) in place of the card or timed flow, clears `card` and `timed`, and wires the document click and `keydown` handlers to `step()` as for the other flows. It keeps `single` state beside them. With judging on the microphone decides (see **Listening in Single note**); with it off nothing here opens it. Opening Settings, a new tune and Play song restart the effect, which starts again at the first note; hiding the page stops it (`visibleKey` follows visibility in Song mode). The tune list and Play song stay enabled, since no phase is passed.

- **State** `{ index, fingering, ended, listening: "off" }`: the current note's index in the song (rests are never current and a tied note is one index), whether its fingering shows, and whether the head moved past the last note.
- **Timers:** on start and on each new note `fingering` is false and a fingering timer starts; when it fires the fingering shows and the advance timer starts; when that fires the next note becomes current. One timer is pending at a time.
- **`step()`** (a click, tap or key): when ended, start again at note 0; with no fingering showing, show it now and start the advance timer; with it showing, move to the next note now. The next after the last note ends: `ended` true, timers cancelled, no score or summary. `stop()` cancels the timer. No tone is played and nothing is graded or stored.
- **View:** `singleNoteView(base, state)` (`single-note-view.ts`) gives a `SongView` with `current` (the index, or -1 when ended so no note is black), `head` (the index, or null when ended), `strip: true`, lanes on, a stopped playhead, no fill, spots, overrun or scoring. `playbackView` and the Tempo view leave `strip` and `head` unset.
- **The fixed head:** `headPlace(index, timeline, tempo, rows)` (`playhead.ts`) is the head's `{ row, x }` at note `index`'s start beat through `playheadPlace`, or null. `SongOverlay` draws it in its own effect (not the frame loop) as a second `.playhead` line from the row's top to its lane's bottom, and calls `onRow` when the head's row changes; it forgets the reported row when the head goes null, so a restart follows back to row 0. The page follows as in Tempo, and the resize follow also applies while a head is shown. `SongStaff` gives `drawSongLines` the `strip` flag and redraws when it changes.
- **The fingering strip:** every row has a strip of `STRIP_HEIGHT` under its lane whether or not a fingering shows, so nothing moves when it appears ([staff](staff.md)). While `single.fingering`, `Card` builds `song.fingering = { name, tab }` and `SongOverlay` draws it in the head's row strip, centred under the head: the letter (`.fingering-name`), then the glyph in the tab font (`.fingering-glyph`), or the placeholder message while the font loads. At 3 or 4 bars per line it may hang over its neighbours' space.
- **Not here:** the song card with waiting, a hint and skip, and `songSource`, are gone.

### Listening in Single note

With judging on (F16-S03) `App` builds `listen` for the flow: `{ listener, watch: createToneWatch(TONE_WATCH_CHECKS), grade, now: () => performance.now() }`, where `grade(index, readings)` calls the [judge](judge.md)'s `gradeTone` with the note's sounding pitch (`soundingPitch(instrument, written)`), `settings.toleranceCents`, `CHECKS` and `lengthMs` from `tonePassLengthMs(note)` (`trace.ts`: `endMs - releaseMs - startMs`, the note's lane segment, the grey box the player sees; the written length for a note slurred into the next). The tone rule lives in `src/core/judge`, so no module or import rule is new.

- **Stream:** opened once per flow, as the card flow does; the state's `listening` is `off`, `opening`, `locked`, `running` or `unavailable` and `App` drives `judgeUnavailable` from it. While it is opening, locked or unavailable the Single note timers apply as with judging off, a locked stream is tried again at the next note, and when it starts running the current note begins listening (the advance timer, if pending, is dropped). The flow state gains `message` and the flow a `tone()` method for the overlay.
- **Listening:** while the stream runs, each new note calls `watch.reset(now())` (with no hold-off: `TONE_WATCH_CHECKS` is `CHECKS` with `holdOffMs: 0`, since no reference tone plays and a hold-off would drop the start of a tone played straight after the last; a sound held through from the last note is not a tone until the player stops, so one pitch held across two notes passes only the first) and cancels any advance timer. The fingering timer still runs, and the advance delay plays no part. Taps work as without the microphone: the first shows the fingering, the next moves on.
- **The tone's end:** a tone starts once sounding readings last the settle time and ends after `TONE_END_SILENCE_MS` of silence, never on a change of pitch. A tone start clears `message`. On an end, `passed` (time within the tolerance at least 75% of the segment, however long it sounded) moves to the next note; `too-short` (most of the sounding time right) sets `message` to `PLAY_WHOLE_VALUE` ("Play the note's whole value") in the pinned bar, kept until the next tone starts, and shows no fingering; `wrong` shows the fingering, which stays until the head moves on. Every end clears the trace and the note keeps listening. A throwing watch or grade leaves the note to its timers and taps.
- **The trace:** `toneSegment(tone, note, sounding, checks)` (`trace.ts`) builds a coverage `Segment` from `flow.tone()`: readings are placed at `note.startMs + (time - tone.startMs)`, only sounding readings become points with cents from `centsFrom` against the sounding pitch, and it is clamped at `note.endMs` so a longer tone draws nothing more; null without a tone. `App` keeps the running trace in a module variable (`activeSingleTrace`, like `activeTimed`) and passes `SongView.tone = { trace, tolerance }` through `singleNoteView`, only while listening runs. `SongOverlay` runs one frame loop while `tone` is set: it writes the trace into the open fill paths of the rows `rowsToUpdate` names, through `segmentPaths` (Tempo's colours and heights: green within the tolerance, amber the right note out of tune, red beyond ±50 cents), clears them when `trace()` is null, and draws the tolerance guides as Tempo does. The segments are Tempo's lane segments, which end where the release starts, so the trace may run past the grey segment into the release gap, up to the written end.
- **The card:** in Single note the song bar shows `message` when set and the `Legend` while judging is on; there is no verdict row or other text.

## Tuner

Tuner mode (F19-S01, [ADR 0014](../decisions/0014-tuner-mode.md)) opens the microphone and shows a staff and a prompt, with no card, song, timer, tone or grading, and nothing stored. `App`'s flow effect has a first branch for it: `createTunerFlow({ listen: { listener, now }, onChange })` (`tuner-flow.ts`, plain TypeScript), ignoring `judgeEnabled`. It keeps `tuner` state beside `card`, `timed` and `single`; each branch clears the others' state. Click and `keydown` call `step()` as elsewhere. The `song === null` guard tests Song mode only, so Tuner passes it. `visibleKey` follows page visibility in Tuner, so Settings opening or the page hiding releases the microphone, and closing or showing reopens it.

- `createTunerFlow` returns `{ start, step, stop }` over `TunerState { listening, note, held }`, where `note` is `{ pitch, cents }` in written pitch or null. `start()` shows `opening` and calls `listener.start`; the result is shown as `running`, `locked` or `unavailable` (a throwing or rejecting `start` is `unavailable`). `step()` while `locked` calls `start` again (the gesture has unlocked audio); otherwise it does nothing. `stop()` calls `listener.stop()`, and a result that arrives after it is ignored. `listen` also carries the tone `watch`, `follow(readings)` and `hold(readings)` (S02). `App`'s `tunerListen()` builds `{ listener, watch: createToneWatch(TONE_WATCH_CHECKS), now, follow, hold }`: `follow` and `hold` call `followNote` and `heldNote` ([judge](judge.md)) with `CHECKS` and `DEFAULT_THRESHOLDS.settleMs`, then convert to written pitch (`pitch - instrument.transposition`). The band in `CHECKS` means readings outside it show nothing, and the watch's settle time means a sound shorter than 200 ms does too. On `running` the flow calls `watch.reset(now())`. Each reading goes to `watch.push`. A `start` clears the hold and shows `follow(tone.readings)` with `held: false`; while the tone sounds the note and its cents are refreshed from `follow(watch.tone().readings)` only when `createReadoutThrottle()` allows it for the reading's time, so at most every `READOUT_INTERVAL_MS`. An `end` shows `hold(event.readings)` with `held: true` at once, and silence after it changes nothing until the next `start`. A throwing watch or helper is swallowed.
- **Card:** with the `tuner` prop `Card` draws `<Staff pitch={tuner.note?.pitch ?? null}>` and a `card-reveal judging` area: `LISTEN_PROMPT` while `locked`, `JUDGE_UNAVAILABLE` while `unavailable`, otherwise `PLAY_A_NOTE` ("Play a note") while there is no note. The other card branches do not render in Tuner. With `tuner.note` set the area shows the note's name (`formatPitch`), its tablature from `glyphFor` (nothing at all when the note is outside the instrument's range, with no placeholder), a verdict row and the `PitchGraph` centred on the note (`expected` is the note, `cents` the offset, label `"D4, 12 cents sharp"`). The verdict row in tune is `✓ In tune` with the class `verdict-correct`; off tune it is the text from `tunerVerdict` with the class `verdict-off` (a darker amber than the lane's, for 4.5:1 text) and no icon, so colour is never the only signal. `LISTEN_PROMPT` and `JUDGE_UNAVAILABLE` take precedence over a note. `App` passes the tolerance as `toleranceCents`.
- **Staff:** the stave shows with no note (see [staff](staff.md)). `TUNER_STAFF_OPTIONS` is `STAFF_OPTIONS` with `lowest` and `highest` widened by an octave either way (`instrument.lowest - 12`, `instrument.highest + 12`), so a note outside the instrument's range can be drawn without `noteLayout` throwing.
- **Header:** no title, tune list, tempo or Play song button in Tuner; `headerSong`, `playButton` and `tuneChoice` give nothing outside Song mode.

## Settings view

`App` holds `settings` and `open` in state. A Settings button is shown on every card (in the sticky header, so it never covers the staff and does not move it; the header holds only the app name while the view is open). Opening clears the card and sets `open`; the card is not rendered while the view is open. The card-flow effect runs only while `open` is false and is keyed on `[settings, open]` (plus page visibility while judging, see [Listening](#listening)): opening runs its cleanup (`flow.stop()`, listeners removed), so the timer stops and clicks and keys no longer drive the card. Closing re-runs it with a pool, reveal delay and advance delay (`settings.autoAdvance ? settings.advanceDelaySeconds * 1000 : null`) built from the current settings, so `start()` draws a new card with a fresh timer. A section with a message to show (today the sharps-blocked note) cannot be closed and opens by itself when the message appears. ## Listening

With `listen`, the flow judges each card from the microphone (F04-S05):

- **Deal:** the card is shown at once. If the stream already runs, the tracker is reset with `now()` (so the [judge](judge.md)'s hold-off counts from the card's appearance), the **listening window** opens and the reveal delay starts. Otherwise `listener.start(onReading)` is called and the state is `opening`; the reveal delay and window wait for its result.
- **Result:** `running` marks the stream as open for the rest of the flow, then opens the window and starts the reveal delay. `locked` starts the reveal delay with no window, and the next deal calls `start` again. `unavailable`, a throwing `start` or a rejected promise marks the flow unavailable: every later card is dealt with `listening: "unavailable"` and behaves as with judging off, and `start` is not called again in this flow. A counter bumped on each deal and on `stop()` makes a result for a replaced card only record whether the stream runs or is unavailable, and makes a result after `stop()` do nothing. A `step()` while opening reveals at once with `none`; the late result then updates `listening` but opens no window.
- **Window:** while it is open, each reading goes to `tracker.push`. On a tone, `grade(pitch, hz)` decides `correct` or `incorrect`, the reveal timer is cancelled and the card reveals at once with that verdict. A timed reveal or a `step()` reveal gives `none`. Every reveal closes the window, so readings during the reveal (the F03 tone) are ignored, and the tone and advance timers run as without judging. A throwing `push`, `reset` or `grade` is swallowed, closes the window and leaves the card to its reveal timer.
- **Retry** (F18-S03): with auto-advance off (`retryAdvanceMs` set), a card revealed while the stream runs is judged first as above. A miss (a wrong note, a timed reveal or a tap) shows the card with `retry: "listening"`, graded once as a miss, and does not move on: after the tone's end (`tone.delayMs + tone.durationMs`, or at once without a tone) the tracker is reset and the window opens again, so its hold-off (500 ms) drops the room tail and the card's own note is never heard as the answer. A settled tone then goes to `grade`: `correct` shows `verdict` correct with `retry: "right"`, closes the window, grades nothing more and deals the next card after `retryAdvanceMs`; `incorrect` shows the new verdict (the row and graph follow it), resets the tracker and keeps listening. A tap deals at once. A card played right first time reveals as correct and deals after the later of `retryAdvanceMs` and the tone's end. A throwing tracker or grade closes the window and the card waits for a tap. With judging off, the microphone locked or unavailable, or auto-advance on, a revealed card behaves as before. The advance and the tone wait share the reveal timer's slot, so `step()`, a new deal and `stop()` cancel them.
- **Stop:** `stop()` also calls `listener.stop()`, releasing the microphone.

When the stream is open: while the drill is showing with judge on (or in Tuner, which always listens) and the page visible. `App` keys the flow effect on `[settings, open, settings.judgeEnabled || tuner ? visible : true]` (`visible` from `visibilitychange`) and creates no flow while judging and hidden, so opening Settings, turning judge off, or hiding the page runs `flow.stop()` and releases the stream; closing Settings or showing the page again creates a new flow that reopens the stream and deals a fresh card, whose reveal delay waits for it. With judging off visibility changes nothing. `App` keeps `judgeUnavailable`, set when the flow reports `unavailable` and cleared on `running` or with judge off, and passes it to `Settings`, whose Microphone section then shows the notice and is open.

All layout is CSS in `app.css`; no JS sizing.

- **Viewport and touch:** `index.html` uses `viewport-fit=cover` and does not disable zoom. `html, body` set `touch-action: manipulation` (no double-tap zoom, pinch kept). `body` has no margin.
- **Safe areas:** `main` pads `max(1rem, env(safe-area-inset-*))` on all four sides, with `box-sizing: border-box` and `min-height: 100dvh`. Nothing hides `overflow-x`.
- **Header:** `.app-header` is a sticky (`top: 0`, `z-index: 2`, `Canvas` background) nowrap flex row: the app name, then, when `tuneChoice` gives a list, the tune list (`.app-header-tunes`, a `select` that takes the title's place: `flex: 1 1 auto`, `min-width: 0`, one line with an ellipsis, greyed out when disabled), otherwise the song's title (`.app-header-title`, one line with an ellipsis, full text in `title`) when `headerSong` gives it, then the tempo list (`.app-header-tempo`, a `select` labelled "Tempo" from `tempoChoice`; `flex: 0 0 auto` so it keeps its width, 44 px high, greyed out when disabled), then the Play song button (when `playButton` gives one) and the Settings button. `main` has no top padding; the header carries it, so nothing shows above it once stuck. Below 480 px the name's font shrinks. `html`'s `scroll-padding-top` keeps a focused Settings control clear of it.
- **Song bar and page (F10-S03):** `main` is a flex column; `.card` has `width: 100%` so its auto margins still centre it and random cards keep their size. A song card (`.card-song`, `flex: 1 0 auto`, a flex column) has no reveal area: after the staff it renders `.song-bar` (`Card` holds a `bar` ref for F10-S04), holding the start prompt (`timed === "ready"`), the live readout, the summary and tuning lines and, while judging, the `Legend`. With judging off the bar holds the prompt, nothing while playing, and "End of song" at the end, with no legend. The bar has no controls, so the document click handler still starts the song from a tap on it. `.song-bar` is `position: sticky; bottom: 0; margin-top: auto; z-index: 1` with a `Canvas` background, a top border and bottom padding `max(0.5rem, env(safe-area-inset-bottom))`: sticky and in flow, it holds the bottom of the screen while scrolling, takes its own room after the last line so the last lane clears it at the page end, and a change of its height moves nothing above it; a short song's bar sits at the screen bottom through `margin-top: auto`, with the font licence footer below it. **Height cap:** `SongStaff` sets `--row-aspect` (`layout.width / ROW_HEIGHT`) on its box; `.song-staff` is capped at `max-width: calc((100dvh - var(--song-chrome)) / 2.2 * var(--row-aspect))` and centred (`--song-chrome`, 13rem, reserves the header and bar), so two rows with the header and bar fit a 1024x768 window at the default 2 bars per line; phone widths are unchanged and do not scroll sideways.
- **Card and staff:** `.card` is centered with `max-width: 28rem`. [`drawStaff`](staff.md) sets a view box, so the `.staff` wrapper sizes the SVG: 100% wide up to 220 px, up to 440 px from 600 px wide, with `aspect-ratio: 220 / 150` so the box depends only on viewport width, never on `revealed`.
- **Reveal area:** fixed height per breakpoint (12rem, 15rem from 600 px, 9rem when the viewport is 480 px high or less), so revealing never moves the staff. The placeholder uses the same box as the glyph.
- **Scrolling:** vertical only. No `100vh` heights; a short landscape phone scrolls if it must.
- **Touch targets:** buttons, `<select>`s and number inputs have `min-height` and `min-width` of 44 px and a 16 px font (no focus zoom on mobile). Checkboxes are 1.5rem inside a label row at least 44 px tall.
- **Judged reveal (F04-S06):** `.card-reveal.judging` has its own fixed height for name, glyph, verdict row and graph: 17rem (glyph 7rem), 21rem from 600 px wide (glyph 9rem), 13rem below 480 px tall (glyph 5rem, graph capped at 16rem wide). The graph is `width: 100%` up to 20rem, so it fits at 360 px. Verdict colors on the light background: correct `#17692e` (6.8:1), incorrect `#b3261e` (6.5:1), nothing heard `#555` (7.5:1); the played marker `#1b4f9c`. `.card-status` holds the listening prompt or unavailable notice inside the reveal area.
- **Settings view:** `.settings` is 100% wide up to 24rem; selects and number inputs are capped at 10rem with `min-width: 0` so label text wraps instead of overflowing at 360 px.
- **Settings sections and footer:** `.settings-section` summaries are at least 44 px tall with a pointer cursor; the label rows inside keep their flex layout. `.settings-footer` is `position: sticky; bottom: 0` with an opaque `Canvas` background, in flow after the sections, so it takes its own space at the end of the view and covers nothing when scrolled to the bottom. `html { scroll-padding-bottom: 4rem }` scrolls a focused control or message clear of it.
- **Footer:** wraps (`overflow-wrap: anywhere`) inside the page width.

## Font and license

The font loads on page load, not at reveal, so it is usually ready when the delay ends. The family name is the file name without its extension ([tab](tab.md)). `vite.config.ts` sets `build.assetsInlineLimit` so files under `data/fonts/` are emitted as files, never data URIs. `dist/assets/` holds the `.ttf` and `OFL-*.txt`, and the footer links the license. No font request goes to another host. See [`data/fonts/README.md`](../../../data/fonts/README.md) and [ADR 0002](../decisions/0002-tablature-from-panzi-font.md).
