# app

`src/app/`

## Purpose

The Preact UI that wires the layers together: loads the instrument, shows a card, reveals it after a delay or on click or key press, advances to the next card, loads the tablature font and shows its license. Drawing is delegated to [`drill`](drill.md); this layer owns input and the timer.

## Public interface

- `App`: loads the alto C instrument, starts loading its font once on mount, and reads `data/settings/defaults.json` at build time through `parseDefaults` ([settings](settings.md)), and in one `useEffect` creates the card flow with a pitch source and its delay: `songSource(song.pitches, onIndex)` when `useSong` is on (the index picks the dealt note's `beats`, held as `cardBeats` and passed to `Card`, so a song card shows its note's length; random and need cards pass none and draw a whole note) and a valid song is held (`poolFor` is then never called, so a range left stale by the song is never built), otherwise `randomSource(poolFor(settings), Math.random)`, or, when `smartSamplingApplies(settings)` ([settings](settings.md)), `needSource(poolFor(settings), () => scoresRef.current, Math.random)`. `scoresRef` is a `useRef<Scores>` loaded once at mount with `loadProgress(browserStorage(), instrument)`, so scores from before a reload are used; it is a ref, not state, because a grade must not re-run the flow effect and deal a new card. When smart sampling applies the flow gets `onGraded`, which sets `scoresRef.current = applyGrade(scoresRef.current, pitch, grade)` and then calls `saveProgress(browserStorage(), instrument, scoresRef.current)` at once; otherwise `onGraded` is null, so nothing is graded or written. Song cards are never drawn by need and never graded. While `useSong` is on and no song is held yet (the load-time parse is running), no flow starts and no card shows. The song is a dependency of the effect, so closing the settings view starts at the first note. The flow's delay is `delaySeconds * 1000`. The flow gets `wait: settings.useSong && settings.judgeEnabled` (F07-S01); the song branch is only reached with a song held, and the flow restarts at the first note as for any change of settings. The effect mirrors the flow's state into `useState`, calls `start()` and calls `stop()` on cleanup. The same effect owns input: `click` on `document` and `keydown` on `window` each call `flow.step()` once. It ignores `keydown` with `event.repeat` or Ctrl/Meta/Alt held, and clicks inside an `<a>`, `button`, `input`, `select` or `label` (the license link and the settings controls). The effect also passes the tone when `settings.soundEnabled`: `delayMs` is `soundDelaySeconds * 1000`, `play(p)` calls the tone player with `soundingPitch(instrument, p)` and `soundDurationSeconds`, `stop()` stops it; with play note off the tone is null. A module-level `audio = createAudio(browserAudioFactory())` and `player = createTonePlayer(audio)` are the app's one audio context and player ([audio](audio.md)). A mount-only effect adds `click`, `keydown` and `touchend` listeners on `window` with `{ capture: true }` that call `player.unlock()`, so the unlock runs before `flow.step()` on the same gesture; they are removed on cleanup. Opening the settings view runs the flow effect's cleanup, whose `flow.stop()` cancels a pending tone and stops a playing one. Nothing extra is shown when audio is unavailable. A module-level `listener = createListener(audio, browserListenerEnv())` shares that context ([audio](audio.md)). With `settings.judgeEnabled` the effect passes `listen` (see [Listening](#listening)): a fresh `createToneTracker({ ...DEFAULT_THRESHOLDS, band: frequencyBand(instrument) })`, `grade: (p, hz) => judge(soundingPitch(instrument, p), hz, settings.toleranceCents)` and `now: () => performance.now()` ([judge](judge.md)); with judging off `listen` is null. It renders a `Card` for the current state and the license footer.
- `type PitchSource = (previous: Pitch | null) => Pitch`, `randomSource(pool, random)` and `songSource(pitches, onIndex?)` (`card-flow.ts`, F05-S04; `onIndex` hears each dealt note's position): where a card's pitch comes from. `randomSource` is `drawPitch` over the pool (never the same pitch twice in a row, unless the pool is one pitch). `songSource` keeps its own index in a closure and ignores `previous`, taking each pitch from the drill's `nextInOrder`, so the notes come in order, a repeated note is shown again, and the song loops after the last; it draws nothing at random. Each flow gets a new source, so the position starts at the first note whenever a flow starts (page load, closing the settings view, a changed song or other setting) and is never saved.
- `createCardFlow({ next, delayMs, advanceDelayMs, tone?, listen?, onChange })` (`card-flow.ts`, plain TypeScript): returns `{ start, step, stop }` over the state `{ pitch, revealed, verdict, hint, listening }`. `hint` (F07-S02) is false on every deal and true while a waiting card shows its letter and tablature early; it stays on a reveal. `verdict` is null while hidden and a `Verdict` once revealed: `{ grade: "correct" | "incorrect", frequency }` from the judge, or `{ grade: "none" }`. `listening` is `off`, `opening`, `locked`, `running` or `unavailable`. Without `listen` every reveal has `none` and `listening` is `off`, and the flow is exactly as below. `start()` takes the first pitch from `next(null)` and starts the reveal timer. `step()` reveals an unrevealed card and cancels the timer, or, if revealed, takes the next pitch from `next`, hides it and restarts the timer from zero; never both. When `advanceDelayMs` is not null, every reveal (timed or by `step()`) starts an advance timer that deals the next card, so the delay counts from the reveal; it is held in the same slot as the reveal timer, so only one timer is ever pending (none for a hidden card's advance). A `step()` on a revealed card deals at once and cancels the advance timer, so it never fires. `null` turns auto-advance off. `stop()` cancels whichever timer is pending. The optional `tone` (`CardTone { delayMs, play(pitch), stop() }`, null or absent for silence) sounds the note on every reveal, timed or by `step()`: with `delayMs` 0 `play` is called synchronously inside the reveal (so it runs on the input gesture), otherwise a separate sound timer starts at the reveal; a hidden card has none. Dealing the next card (a `step()` or the advance timer) and `stop()` cancel the sound timer and call `tone.stop()`, so the advance stops the tone even when delay plus duration equals the advance delay. A throwing `tone.play` or `tone.stop` is swallowed. `needSource(pool, scores, random): PitchSource` (F06-S04) is `drawWeighted(pool, previous, p => drawWeight(scores(), p), random)` ([drill](drill.md), [progress](progress.md)); it reads `scores()` on every draw, so a grade applied since the last card counts, and scores for pitches outside the pool are untouched. The optional `onGraded(pitch, grade)` is called at most once per card, from `reveal()` right after the revealed state is shown, only when `listen` is set and the card's `listening` is `running`: `correct` for a correct verdict, `miss` for an incorrect one or `none` (a timed reveal or a tap). It is not called for `opening`, `locked`, `unavailable` or `off`, and a throwing `onGraded` is swallowed like `tone`. The optional `listen` (`CardListen { listener: { start, stop }, tracker: { reset, push }, grade(pitch, hz), now() }`) judges each card before its reveal; see [Listening](#listening). The optional `wait` (F07-S01 and F07-S02, default false) makes a card wait for the correct note; see [Waiting for the correct note](#waiting-for-the-correct-note). `WRONG_VERDICT_MS` (1000) is exported from `card-flow.ts`.
- `Card({ pitch, revealed, listening?, judging?, verdict?, instrument, staffOptions, font })`: presentational. The staff above a fixed-height reveal area; `judging` (from `settings.judgeEnabled`, not from `revealed`) adds the `.judging` class, which gives it a taller fixed height. Until revealed the area is empty, except for a `.card-status` line: `LISTEN_PROMPT` ("Tap or press a key to start listening") while `listening` is `locked`, and `JUDGE_UNAVAILABLE` while it is `unavailable`. The texts are in `judge-text.ts`, shared with `Settings`. When revealed it shows `formatPitch(pitch)` and the [`tabView`](tab.md) of the instrument's glyph for that pitch: the glyph in its font family, or the placeholder message while the font loads or after it fails. With `judging` and a verdict (and listening not `unavailable`), a verdict row follows: an icon (`✓`, `✗` or `–`, `aria-hidden`) and a text label (Correct, Incorrect, Nothing heard) in a class per grade (`verdict-correct`, `verdict-incorrect`, `verdict-none`), so color is never the only signal. For correct and incorrect the row also holds the judged note (`judgedNote(...).label`, such as `C♯5 +23¢`) and a `PitchGraph` follows; for `none` nothing more. `Card` takes `hint` (F07-S02): the name and glyph block shows when `revealed || hint`, followed by the verdict row and graph when there is a verdict, so the hint, a wrong verdict and a judged reveal share one layout. The reveal area gets a `card-hint` class (muted look only, no height change). With `judging` and a verdict on an unrevealed card (a wrong note while waiting, F07-S01), the same verdict row and `PitchGraph` render in the reveal area with no name or glyph; the fixed-height `.judging` area keeps the staff steady. Judge off renders exactly as after F03.
- `verdict.ts` (plain TypeScript): `judgedNote(instrument, hz)` (`nearestPitch`, minus the instrument's transposition, so the note is written pitch; `{ pitch, cents, label }` with the label from `formatCents`), `playedOffset(instrument, writtenExpected, hz)` (`centsFrom` the card's sounding pitch, for the graph) and `graphLabel(played, cents, expected)` ("Played C♯5, 23 cents sharp of C5", `flat`, or `in tune with`).
- `PitchGraph({ expected, cents, playedName, label })`: a thin SVG over [`pitchGraph`](graph.md) with a 320x64 `viewBox` and `width: 100%`: the axis with a tick and name per semitone, a dashed line for the expected pitch, a dot for the played pitch (a triangle pointing out of the edge when pinned), and the played note name with the offset above its marker (anchored inward near the edges). `role="img"` with `aria-label` from `graphLabel`.
- `Staff({ pitch, options, beats? })`: draws the staff with [`drawStaff`](staff.md); `beats` is the note's length, a whole note when absent.
- `startRevealTimer(delayMs, onReveal): () => void`: a `setTimeout` wrapper that returns a cancel function.
- `Section({ title, summary, hasMessage?, initiallyOpen?, children })` (`Section.tsx`): a native `<details class="settings-section">`. Its `<summary>` shows the title and, only while closed, the summary line. The open state is local (`useState`, never stored); `onToggle` runs the browser's state through `sectionOpen` and writes it back, and an effect opens the section when `hasMessage` becomes true. `section.ts` (plain TypeScript) holds `sectionOpen(requested, hasMessage)` (`requested || hasMessage`) and `formatSeconds(n)` (`"3 s"`, `"0.5 s"`). A later feature adds a section with a `<Section>` and no change to the structure.
- `Settings({ instrument, settings, onChange, onClose, judgeUnavailable?, songState, onSong, onResetProgress })`: the settings view: a "Cards" `Section` (open first), a "Sound" `Section`, a "Microphone" `Section` and a "Song" `Section` (all start closed), followed by a Close button in a sticky footer. Two `<select>` pickers (`lowestOptions` / `highestOptions`, labelled with `formatPitch`), an include-sharps checkbox, a reveal delay number input (`min` 0.5, `max` 30, `step` 0.5), an auto-advance checkbox, an advance delay number input (same bounds; stays enabled when auto-advance is off) and a "Use smart sampling" checkbox make up Cards. The smart sampling checkbox is disabled, its value kept, by `smartSamplingDisabled` (judging off or a song in use); while judging is off `smartSamplingNote` puts "Needs Judge my playing" under it. While a song is in use Cards shows `SONG_IN_USE` ("A song is in use, so the note range, sharps and smart sampling do not apply."). Under them a "Reset progress" button (never disabled, a normal button so it keeps the 44 px target and a click on it does not step a card) asks `window.confirm(RESET_CONFIRM)` ("Reset progress? This can't be undone.") and calls the `onResetProgress` prop only on confirm; cancelling does nothing. `App` passes `onResetProgress` that sets `scoresRef.current = resetProgress(browserStorage(), instrument)`; no setting changes, so the flow is not rebuilt. The Cards summary line is unchanged. Nothing draws by need yet (F06-S04). Sound holds a "Play note" checkbox, a sound delay input (`min` 0, `max` 30, `step` 0.5) and a sound duration input (`min` 0.5, `max` 30, `step` 0.5), both disabled with their values kept while play note is off. Microphone holds a "Judge my playing" checkbox, an always-shown help line under it (`JUDGE_HELP`, a `settings-note`: the microphone is open while drilling with judge on, only the time before each reveal is analysed, nothing is stored or sent), and a "Tolerance (¢)" number input (`min` 10, `max` 45, `step` 1) through `applyToleranceInput`. `judgeUnavailable` (default false) is the Microphone section's `hasMessage` and shows `JUDGE_UNAVAILABLE` under the help line. The sharps checkbox is disabled while sharps are on and `canTurnSharpsOff` is false, with the reason from `setIncludeSharps` shown beside it. The auto-advance and play note checkboxes go through `setAutoAdvance` and `setSoundEnabled`; each is disabled while off when turning it on would break the sound sum rule ([settings](settings.md)), with `soundTooLongReason` shown under it. The advance delay and both sound inputs go through `editTiming`; a rejected edit leaves the old value and shows the reason under the edited input, held in local state and cleared by any accepted edit or when the view closes. A section with any of these messages stays open. Every change calls `onChange`, so it is saved with the rest.

**Song section** (F05-S03): a monospace `textarea` (placeholder `SONG_EXAMPLE` (`song-form.ts`, imported from the defaults so the text exists once), the default song text from `data/settings/defaults.json`, a short Mary Had a Little Lamb, shown greyed when the box is empty so the format is clear; on a fresh profile it is also the saved text and the song) bound to a local draft (started from the saved `songAbc`, so reopening drops a failing text), a help line, a link to `https://editor.drawthedots.com/` (`target="_blank"`, `rel="noopener noreferrer"`), a result region (`role="status"`, `aria-live="polite"`; it also shows `NO_TEMPO_NOTE` while the held song has no `Q:` line) and the "Use song" checkbox, disabled by `canUseSong(songState.song)`. Each edit runs `parseAbc(draft, instrument)`; a result older than the latest edit (a counter in a ref) is ignored. A passing text calls `onChange` (saved) and `onSong`; a failing text shows its problems and calls neither, so the last good song stays; an emptied box is filled with `SONG_EXAMPLE` at once and parsed like any edit, so the box is never left empty. A section showing problems stays open. The song is not drawn. While `useSong` is on, the Cards section's lowest, highest and include-sharps controls are disabled, with a line saying a song is in use; their values are kept.

**Keep tempo** (F08-S02): the Song section holds a "Keep tempo" checkbox after "Use song", disabled while use song is off (its value kept); `songSectionSummary` adds `, keep tempo` when both are on. A "Metronome" checkbox follows it, disabled unless `keepTempoApplies(settings)` (its value kept). When `keepTempoApplies(settings)` ([settings](settings.md)) and a song is held, the flow effect builds a timed flow instead of the card flow: no tone, no reveal or advance delay, and the card flow's code is not touched. `App` keeps a `timed` state beside `card`; a card and a timed song never show together. The flow's clock is `clicker.now()` (the audio clock), falling back to `performance.now() / 1000` with no context, so a song without audio runs silent but in time. Clicks and keys call `step()` as they do for the card flow (the capture-phase unlock runs first). The page-visibility key also applies to a timed song with judging off, so hiding the page, opening Settings or changing a setting stops it and its clicks, and showing the drill again shows the first note with the start prompt.

`timed-flow.ts` (plain TypeScript): `createTimedFlow({ song, clock, clicker, metronome?, listen?, outputLatency?, onChange })` with `start()`, `step()` and `stop()`; `LEAD_SECONDS` (0.1), `METRONOME_LOOKAHEAD_SECONDS` (1), `INPUT_ALLOWANCE_MS` (55), `FALLBACK_LAG_MS` (100) and `scoringLagMs(outputLatency)`. State `TimedState { index, pitch, beats, phase, countBeat, listening, summary }`, where `index` is the shown note's index in the song and `beats` its length, phase `ready | count-in | playing | summary`, and `countBeat` the count-in beat clicking (0 from `t0`, one more each `beatMs`), null before `t0` and outside the count-in. `start()` shows the first note in `ready`. `step()` in `ready` or `summary` starts the count-in: `t0 = clock.now() + LEAD_SECONDS`, one click per `countIn(meter, tempo)` beat from `t0`, and the first slot at `t0 + beats * beatMs / 1000`; in `count-in` and `playing` it does nothing. Slot boundaries are absolute times, the first slot's start plus the cumulative sum of `songSlotsMs`, never a delay added to the last. One `setTimeout` waits for `boundary - clock.now()` (rounded up); when it fires before the clock reaches the boundary (a resuming audio context's frozen clock) it re-arms, so a card never shows early and the song cannot drift from the clicks. One scoring lag after the last slot ends the phase is `summary`, with the [coverage](coverage.md) result as `summary` (see below); until then the last note stays shown in `playing`. A step starts the count-in again with a fresh scoring. `stop()` cancels the timer, calls `clicker.stop()` and releases the microphone. A null clicker keeps it silent but in time. With `metronome` on (`App` passes `metronomeApplies(settings)`), clicks continue the count-in's beat grid: one at the first slot's start and every `beatMs` after it, for every beat strictly before the last slot's end, so there is no gap or double at the first slot. They are scheduled a batch at a time: at the count-in for the first slot plus the lookahead, and at each slot start for the beats up to that slot's end plus the lookahead. Nothing is scheduled once the summary shows; `stop()` and a restart call `clicker.stop()` first, so a restart starts a clean grid. The pickup of a tune is not placed on the bar lines. `Card` takes `timed` (`ready`, `playing`, `summary`) and `timedSummary`: the reveal area holds only `START_PROMPT` ("Tap or press a key to start") in `ready`, nothing while counting in and playing, and the summary text (`summaryText(result)` in `judge-text.ts`: "N% covered", rounded, from the coverage result, or `END_OF_SONG`, "End of song", when the result is null or nothing was graded); no letter or tablature shows. Instead of one note the staff shows lines of music: `App` memoises `songLines(song, settings.barsPerLine)` and passes `Card` a `song` view (`{ lines, meter, barsPerLine, current, countBeat }`, where `current` is `timed.index`, or -1 in `ready` and the count-in so every note is grey; `countBeat` is the flow's, 0 until the first click, so the first rest is lit while waiting for the tap, and null once playing); `Card` then renders `SongStaff` (`Staff.tsx`), which calls `drawSongLines` ([staff](staff.md)), and takes the `card-song` class, which widens the card to 56rem. `SongStaff` draws the staff only when `lines`, the first line on show (`lineOfNote(lines, current)`), the options, the meter or `barsPerLine` change; on a change of `current` or `countBeat` it calls `colourSong`, so a note change never redraws VexFlow. Its `song-staff` box is `position: relative` with an `aspect-ratio` set from the drawn view box, which does not change with the lines shown, so the card keeps its height when the rows change.

**The lane** (F09-S04): a timed song's card draws a lane under each staff row, with judging on or off (random and untimed song cards use `Staff` and are unchanged). `App` builds `buildTimeline(song, tempo)` (the song's tempo or `DEFAULT_TEMPO`) and passes it and the tempo in the `song` view. `lane.ts` (plain TypeScript): `laneSegments(timeline, lines, layout, tempo)` gives `{ row, x0, x1, kind: "note" | "rest", graded, index, starts, ends }` (`row` an index into the layout's rows) for every note and rest on each row: its written length in beats (the timeline's ms times tempo over 60000) clipped to the row's beats and turned into x by `rowMap(...).span`. A note tied over a bar line is one continuous segment and a note over a line break has one on each row; the count-in bar has none. `SongOverlay.tsx` is an SVG over the staff with the same view box (`pointer-events: none`, `aria-hidden`): one `<path>` of rectangles for graded segments (`.lane-graded`, neutral grey) and one for ungraded ones (`.lane-ungraded`, lighter), each rectangle running from the row's `laneTop` to `laneBottom` with a 1-unit gap between neighbours. It is rebuilt when the layout changes and holds no per-frame state.

**The playhead** (F09-S05): `TimedState` gains `origin`, the flow clock's seconds at the first note's start (set in `run()`, null in `ready`). `playhead.ts` (plain TypeScript): `playheadBeat(clockNow, outputLatency | null, origin, tempo)` is the time the player hears in beats, `(clockNow - (outputLatency ?? 0) - origin) * tempo / 60`, negative during the count-in; the clock is the audio clock, or the page clock when there is no audio (the flow's fallback), with no latency then. `playheadPlace(beat, rows)` gives `{ row, x }` (an index into the layout's rows): a row holds the beats from its first stop to its last (its end bar line), so a beat at the end of a line is on the next row at its first note, and the playhead jumps to the other row; before the first row it waits at its start and past the last at its end; x comes from `rowMap(...).beatToX` over the row's stops without the bar lines that share a beat with the next bar's first note (otherwise the line would run to the bar line and jump across the gap to the note when the beat arrives; it now glides over it, a little faster there), so it is at each note's x when the note is due, and runs through the count-in bar's rests in time with the clicks. (The story's `lineOf` argument is not needed: the rows carry their stops.) `SongOverlay` holds one `<line class="playhead">` across the current row and its lane (`top` to `laneBottom`). While the song's `playhead.running` (phase `count-in` or `playing`, with an origin) one `requestAnimationFrame` loop sets the line's `x1`, `x2`, `y1` and `y2` from `playhead.now()` and `playhead.outputLatency()` (`outputLatencySeconds(audio)`), with no Preact state and no VexFlow. The loop is cancelled by the effect's cleanup when the song stops running (the summary), when the layout changes (restarted at once) and when the overlay unmounts (Settings, judging toggled, page hidden all remove or rebuild the flow); a restart from the summary starts it again from the count-in. At the summary the line stays where it stopped. The playhead is not pulled back by the scoring lag, and the note to play is still black.

**Live fill and readout** (F09-S06): `TimedFlow` exposes `progress()`, the coverage run's `Progress` (null when nothing is scored and after the summary), and `reading()`, the newest raw microphone reading. `trace.ts` (plain TypeScript): `traceY(cents, laneTop, laneBottom)` maps `±TRACE_SPAN_CENTS` (150) linearly onto the lane, sharp upwards, clamped to the edges; `traceColour(cents, tolerance)` is `green` within the tolerance, `amber` up to ±50 and `red` beyond; `segmentPaths(segments, rows, tempo, tolerance)` returns, for each row, one path string per colour of filled rectangles (`LaneRow`s from `laneRows(lines, layout)`: a row's beats, its `rowMap` and its lane). On a note each sounding reading of a segment is a `TRACE_THICKNESS` (3) line from its time to the next reading's (or the segment's end), at its offset's height and colour, kept inside the lane; a wrong reading is drawn at its offset within the span and, beyond it, pinned to an edge and red (it is beyond ±50, so red either way); silence on a note draws nothing, leaving the neutral lane. On a rest, silence is a green band (`REST_BAND`, 8 units) across the lane's middle and sound a red one. Notes and rests too short to grade are never filled. Segments are placed at song time, so the fill trails the playhead by about the scoring lag. `SongOverlay` has, per row, a settled and an open `<path>` for each colour (12 for two rows), and a path of faint dashed guide lines at ±tolerance and ±50 cents. Its frame loop (the playhead's) reads `progress()` through `FillSource` (`App` gives module-level `fillProgress` and `fillReading`, which follow the active flow): a new `segments` array (a new run) clears everything; segments finished since the last frame are appended to the settled paths and never recomputed; the open ones are redrawn each frame, and only when their path changed. When the rows change the loop restarts and rebuilds the settled paths from the finished segments for the rows now on show, so the row that left takes its fill with it and the other keeps its own. With judging off `fill` is null: there is no scoring, so no fill, guides or readout. **Readout:** `Card` renders an empty `<p class="card-status card-readout">` in the reveal area while a timed song's stream is `running` in the count-in or playing (`readout` prop, from `App`); the overlay's loop sets its text node directly, never Preact. `hearingText(instrument, reading)` in `judge-text.ts` is "Hearing " and `judgedNote(...).label` (the nearest written note and its offset from it, so 62 cents sharp of D4 reads "Hearing D♯4 -38¢"), or `HEARING_NOTHING` ("Hearing nothing") when the reading fails the judge's checks with the instrument's band. `createReadoutThrottle()` returns a function that allows one change per `READOUT_INTERVAL_MS` (100): a change to the text is shown only when it says yes.

**Fault marks** (F09-S07): the core's `progress()` reports each `TimingFault { index, edge, kind }` and each not-separated `JoinFault { before, after, atMs }` as its note finishes, in arrays that only grow; a note with no right-note time has no edges and so no fault, and slurred joins are never checked, so they are never reported. `laneSegments` now marks each segment `starts` and `ends`: whether it holds the note's own start or end, or only a continuation across a line break. `marks.ts` (plain TypeScript): `faultMarks(faults, joins, segments)` gives `{ row, x, shape }`, where `shape` is `start-early`, `start-late`, `end-early`, `end-late` or `not-separated`. A timing mark sits at the start (`x0`) or end (`x1`) of its note's segment on the row that holds that edge; a not-separated join sits at the end of the note before it (the next note's start when only that row is on show), also between two notes of the same pitch. A fault whose edge is on a row not on show gives no mark. `markPath(mark, laneTop, laneBottom)` draws a timing mark in the lane's top quarter, above the trace's centre line: a thin tick on the edge and a small triangle inside the note beside it, pointing left for early and right for late, so the four are told apart by which edge and which way the pointer faces, not by colour; a not-separated mark is a short vertical bar with a cross over it in the lane's bottom quarter. All are one dark colour (`.lane-marks`, filled and stroked). `SongOverlay` has one `<path>` per row for them: its frame loop appends the faults and joins reported since the last frame (it remembers how many of each it has drawn, and starts again when the run's arrays change), so each appears when the core finishes the note, with the fill, and the paths are cleared and rebuilt for the rows on show when the rows change. **Legend:** `Legend.tsx` is a key under a timed song's staff while judging is on: a list of the five marks, each drawn by `markPath` in a small SVG beside its label (`MARK_LABELS`: "Started late", "Started early", "Ended early", "Ended late", "Not separated"), so the key and the lane cannot drift apart. It is part of the card's fixed layout, so the card does not change height as the song runs. A "Bars per line" number input (1 to 4) follows "Metronome" in the Song section, disabled unless keep tempo applies; `applyBarsPerLineInput` in `settings-form.ts` ignores anything but a whole number in range. Untimed song cards also draw their note's length; random and need cards draw a whole note.

**Coverage scoring in timed songs** (F09-S03, replacing F08's per-slot grading): with judging on, `App` passes `timedListenFor(settings)`, a `TimedListen { listener, coverage }` whose `coverage` is the [coverage](coverage.md) options (the tolerance setting, `{ ...DEFAULT_THRESHOLDS, band }` and `soundingPitch` of the instrument), and `outputLatency: () => outputLatencySeconds(audio)`; `App` passes no `onGraded`, so nothing is stored and smart sampling (F06) is unaffected. On the start tap the flow calls `listener.start(onReading)` once (a restart reuses the running stream; a `locked` result is asked again) and sets `listening` to `opening`; the count-in starts when the promise settles, whatever the result (a throw or rejection is `unavailable`), and a result after `stop()` is ignored. When `run()` starts the song with `listening` `running`, it builds `buildTimeline(song, tempo)` and a fresh `createCoverageRun`, and reads the scoring lag once: `scoringLagMs(outputLatency())`, which is the input allowance `INPUT_ALLOWANCE_MS` (55 ms, the measured key-tap figure, to be tuned on desktop and Android) plus the context's `outputLatency` in ms, or `FALLBACK_LAG_MS` (100) when it is not reported. Every reading from then on, the count-in included, goes to the run in song time: `(audioTime - firstSlot) * 1000 - lag` ms, where `audioTime` is the listener's audio-clock stamp and `firstSlot` the flow clock's seconds at the first slot's start (they are the same clock when there is audio); the reading's `envelope` blocks are placed the same way and pushed first. A reading with no `audioTime` is dropped, and the tone tracker is no longer used in timed songs. The last note's sound reaches the scoring one lag after its slot ends, so the phase stays `playing` on the last note until `songEnd + lag`, then the run's `finish()` result becomes `summary`. With judging off, or a stream that is `opening`, `locked` or `unavailable`, no run is made: the song plays in time, the summary is null and shows `END_OF_SONG` straight after the last slot. A scoring that throws is dropped and leaves the song playing in time with a null summary. No note heads are coloured by result: the staff shows the note to play black and the rest grey, and `Card` shows no verdict row for a timed song. Until the live fill (F09-S06) there is no feedback while playing. The microphone is released as in F04 when the timed song stops (Settings, judging off, page hidden).

**Song state and the load-time parse:** `App` holds `songState` (`song`, the validator's `summary`, and the `problems` of the saved text). A mount-only effect parses a non-empty saved `songAbc` once with `parseAbc` (abcjs loads only then; since the defaults hold the example song this now runs on a fresh profile, still as a dynamic import, so the precache is unchanged); a text that fails turns `useSong` off (saved) and keeps the text, so the Song section opens with the problems on first opening. Use song on with an empty text turns off without parsing; a cleared box saves `""` with use song off, and the next load maps `""` back to the example. A stored use song on with an empty text (only by hand-editing storage) loads the example with use song still on. The card flow takes the song as its pitch source (see `songSource` above).
- `song-form.ts` (plain TypeScript): `NO_TEMPO_NOTE` ("No tempo in the tune, using ♩ = 90", built from `DEFAULT_TEMPO`), `songSummary(notes, converted)` ("21 notes, 2 flats converted to sharps"), `problemLine` ("Line 3, note 7: ..."), `songStatus(result)`, `songStateFrom(result)`, `applySongText(settings, text, result)` (passing: saved and a new state; failing: nothing changes but the problems; empty: text cleared, use song off, `result` not read), `canUseSong(song)` and `songSectionSummary(settings)` ("off", "on" or "on, keep tempo").
- `settings-form.ts` (plain TypeScript): `lowestOptions` and `highestOptions` (the written range below/above the other bound, naturals only when sharps are off, so low is never at or above high) and `cardsSummary` (the Cards summary line, such as `A3 to F5, sharps, reveal 3 s, advance 3 s`; `naturals` with sharps off, `advance off` with auto-advance off) and `applyDelayInput` / `applyAdvanceDelayInput` (the new reveal or advance delay only when finite and in 0.5 to 30, otherwise the settings unchanged; they share one check), `soundSummary` (`on, after 0.5 s, for 1.5 s` or `off`) and `editTiming(settings, field, value)` for `TimingField` (`soundDelaySeconds`, `soundDurationSeconds` or `advanceDelaySeconds`): out of bounds or not finite gives the settings unchanged and `rejected: null`; in bounds goes through `setTimings` and returns its reason as `rejected` when the edit would break the sum rule. Sharps changes go through `setIncludeSharps` in [settings](settings.md). `micSummary` (`off` or `on, within 40¢`) and `applyToleranceInput(settings, value)` (the new tolerance only when `isValidTolerance`, otherwise the settings unchanged) serve the Microphone section.
- `settings-store.ts`: `SETTINGS_KEY` (`fingerwise.settings`), `browserStorage()` (`window.localStorage` or null when absent or blocked), `loadSettings(storage, instrument, defaults)` (defaults on null storage, missing key, throwing `getItem` or bad JSON, otherwise `validateSettings`; never throws) and `saveSettings(storage, settings)` (one `setItem` of `toSettingsJson`; no-op on null, swallows a throwing `setItem`). ## Settings view

`App` holds `settings` and `open` in state. A Settings button is shown on every card (in the in-flow header beside the title, so it never covers the staff and does not move it; the header holds only the title while the view is open). Opening clears the card and sets `open`; the card is not rendered while the view is open. The card-flow effect runs only while `open` is false and is keyed on `[settings, open]` (plus page visibility while judging, see [Listening](#listening)): opening runs its cleanup (`flow.stop()`, listeners removed), so the timer stops and clicks and keys no longer drive the card. Closing re-runs it with a pool, reveal delay and advance delay (`settings.autoAdvance ? settings.advanceDelaySeconds * 1000 : null`) built from the current settings, so `start()` draws a new card with a fresh timer. Each change goes through `changeSettings`, which sets the state and calls `saveSettings(browserStorage(), next)`. A stored value is only written when the player changes something.

## Settings sections

The settings controls are grouped into collapsible `Section`s. Cards opens first (`initiallyOpen`); any section added later starts closed. A section with a message to show (today the sharps-blocked note) cannot be closed and opens by itself when the message appears. Open state is not stored, so each time the view opens it starts that way. A closed `<details>` hides its controls from the tab order, and Enter or Space on its summary toggles it natively.

## Listening

With `listen`, the flow judges each card from the microphone (F04-S05):

- **Deal:** the card is shown at once. If the stream already runs, the tracker is reset with `now()` (so the [judge](judge.md)'s hold-off counts from the card's appearance), the **listening window** opens and the reveal delay starts. Otherwise `listener.start(onReading)` is called and the state is `opening`; the reveal delay and window wait for its result.
- **Result:** `running` marks the stream as open for the rest of the flow, then opens the window and starts the reveal delay. `locked` starts the reveal delay with no window, and the next deal calls `start` again. `unavailable`, a throwing `start` or a rejected promise marks the flow unavailable: every later card is dealt with `listening: "unavailable"` and behaves as with judging off, and `start` is not called again in this flow. A counter bumped on each deal and on `stop()` makes a result for a replaced card only record whether the stream runs or is unavailable, and makes a result after `stop()` do nothing. A `step()` while opening reveals at once with `none`; the late result then updates `listening` but opens no window.
- **Window:** while it is open, each reading goes to `tracker.push`. On a tone, `grade(pitch, hz)` decides `correct` or `incorrect`, the reveal timer is cancelled and the card reveals at once with that verdict. A timed reveal or a `step()` reveal gives `none`. Every reveal closes the window, so readings during the reveal (the F03 tone) are ignored, and the tone and advance timers run as without judging. A throwing `push`, `reset` or `grade` is swallowed, closes the window and leaves the card to its reveal timer.
- **Stop:** `stop()` also calls `listener.stop()`, releasing the microphone.

### Waiting for the correct note

With `wait` (F07-S01; `App` sets it for use song with judging on) a card is *waiting* while it is unrevealed, `listening` is `running` and the window is open. A throwing tracker or grade closes the window, which ends the wait, so the card falls back to its reveal timer as in F04.

- **Wrong note:** an `incorrect` grade does not reveal. The state keeps `revealed: false` and gains `verdict: { grade: "incorrect", frequency }`, so the card shows the verdict row and graph. No tone plays and no advance timer starts. The tracker is reset at that moment, so the next verdict comes no sooner than the hold-off plus the settle time. A separate clear timer (`WRONG_VERDICT_MS`, 1000 ms) sets `verdict` back to null; a new wrong verdict replaces the first and restarts it. It is apart from the reveal and advance slot, so the reveal delay still runs. `reveal()`, `deal()` and `stop()` cancel it.
- **Correct note:** reveals as in F04: verdict, window close, tone after its delay, advance after the advance delay or on a tap.
- **Hint and skip (F07-S02):** when the reveal delay runs out on a waiting card, `timedReveal()` calls `showHint()` instead of revealing: it cancels the reveal timer and sets `hint: true`, keeping any wrong verdict; no tone, no advance timer, the window stays open. `step()` on a waiting card with no hint shows the hint at once; with the hint showing it deals the next note (`deal` cancels the clear timer and no tone was started), so the skip plays nothing and starts no extra advance. One step does exactly one of hint or skip. A wrong verdict under the hint shows and clears as above and the hint stays; a correct tone reveals as above. A revealed card deals the next note as before.
- **Not waiting:** without `wait` or `listen`, and while `opening`, `locked` or `unavailable`, the flow behaves as after F05. A card dealt while `opening` waits once the stream runs.

When the stream is open: while the drill is showing with judge on and the page visible. `App` keys the flow effect on `[settings, open, settings.judgeEnabled ? visible : true]` (`visible` from `visibilitychange`) and creates no flow while judging and hidden, so opening Settings, turning judge off, or hiding the page runs `flow.stop()` and releases the stream; closing Settings or showing the page again creates a new flow that reopens the stream and deals a fresh card, whose reveal delay waits for it. With judging off visibility changes nothing. `App` keeps `judgeUnavailable`, set when the flow reports `unavailable` and cleared on `running` or with judge off, and passes it to `Settings`, whose Microphone section then shows the notice and is open.

## Layout

All layout is CSS in `app.css`; no JS sizing.

- **Viewport and touch:** `index.html` uses `viewport-fit=cover` and does not disable zoom. `html, body` set `touch-action: manipulation` (no double-tap zoom, pinch kept). `body` has no margin.
- **Safe areas:** `main` pads `max(1rem, env(safe-area-inset-*))` on all four sides, with `box-sizing: border-box` and `min-height: 100dvh`. Nothing hides `overflow-x`.
- **Header:** `.app-header` is a flex row (title left, Settings button right) in normal flow, so the button cannot overlap the card.
- **Card and staff:** `.card` is centered with `max-width: 28rem`. [`drawStaff`](staff.md) sets a view box, so the `.staff` wrapper sizes the SVG: 100% wide up to 220 px, up to 440 px from 600 px wide, with `aspect-ratio: 220 / 150` so the box depends only on viewport width, never on `revealed`.
- **Reveal area:** fixed height per breakpoint (12rem, 15rem from 600 px, 9rem when the viewport is 480 px high or less), so revealing never moves the staff. The placeholder uses the same box as the glyph.
- **Scrolling:** vertical only. No `100vh` heights; a short landscape phone scrolls if it must.
- **Touch targets:** buttons, `<select>`s and number inputs have `min-height` and `min-width` of 44 px and a 16 px font (no focus zoom on mobile). Checkboxes are 1.5rem inside a label row at least 44 px tall.
- **Judged reveal (F04-S06):** `.card-reveal.judging` has its own fixed height for name, glyph, verdict row and graph: 17rem (glyph 7rem), 21rem from 600 px wide (glyph 9rem), 13rem below 480 px tall (glyph 5rem, graph capped at 16rem wide). The graph is `width: 100%` up to 20rem, so it fits at 360 px. Verdict colors on the light background: correct `#17692e` (6.8:1), incorrect `#b3261e` (6.5:1), nothing heard `#555` (7.5:1); the played marker `#1b4f9c`. `.card-status` holds the listening prompt or unavailable notice inside the reveal area.
- **Settings view:** `.settings` is 100% wide up to 24rem; selects and number inputs are capped at 10rem with `min-width: 0` so label text wraps instead of overflowing at 360 px.
- **Settings sections and footer:** `.settings-section` summaries are at least 44 px tall with a pointer cursor; the label rows inside keep their flex layout. `.settings-footer` is `position: sticky; bottom: 0` with an opaque `Canvas` background, in flow after the sections, so it takes its own space at the end of the view and covers nothing when scrolled to the bottom. `html { scroll-padding-bottom: 4rem }` scrolls a focused control or message clear of it.
- **Footer:** wraps (`overflow-wrap: anywhere`) inside the page width.
